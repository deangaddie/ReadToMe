# Web front end — how it is built and how to extend it

The UI is the web app in `src/Read2Me.Web`, served by the host at `/app` (`/` redirects there): custom elements rendered with lit-html, signals from `@preact/signals-core` behind a small adapter, `@microsoft/signalr` for the hub, on Bun with no framework ([ADR 0014](../adr/0014-native-web-front-end-replaces-angular.md)). Those three are the only runtime dependencies; adding one needs an ADR. Bun 1.4.2 (pinned by `packageManager`) is the toolchain; no Node. Its `README.md` has the command list; this page is what an agent needs beyond it. Evergreen Chromium and Firefox are both supported, so anything the app uses must ship in both or carry a cheap fallback (a native `<select>` under `@supports (appearance: base-select)`; tooltips are JS-triggered because Firefox has no `interestfor`).

It is a thin view over the agent API ([api.md](api.md)) and the live hub, and holds no book logic of its own. Vocabulary: [context/web.md](../../context/web.md).

## Run, build, test

| Want | Do |
|---|---|
| App on the host | `pwsh scripts/build-web.ps1` then `dotnet run --project src/Read2Me.App` → web app at `/app` (`/` redirects there) |
| Dev loop with HMR | host running on `:5000`, then `bun run dev` in `src/Read2Me.Web` → `http://localhost:4300/app/` (proxies `/api`, `/hubs`, `/workspace`, `/openapi`, `/audio-preview`, `/preview-source`). Restart it after adding a file reached through `@app/*` |
| PR gate for the web project | `bun run check` (`format:check` + lint + typecheck + `icons:check` + `help:check` + `bun test` + build) or `pwsh scripts/build-web.ps1 -Check` |
| One spec | `bun test src/app/core/router.spec.ts` |
| Browser tests | build the bundle, then `dotnet test src/Read2Me.E2eTests --filter-namespace 'Read2Me.E2eTests.Tests.Web*'`; without a bundle every browser test skips with the command to run |
| The same suite in Firefox | `R2M_E2E_BROWSER=firefox dotnet test src/Read2Me.E2eTests` (the gate adds the browser-tests namespace filter above: the API and host tests open no browser, so Chromium covers them) |
| Every CI stage, locally | `pwsh scripts/check.ps1` (`dotnet build`, API contract, web check and build, unit, E2E Chromium, E2E Firefox over the browser tests only; `-SkipInstall` once dependencies are current; a failing E2E stage keeps its traces, screenshots and the `dotnet test` SDK trace in `.artifacts/e2e/<time>-<browser>/`, newest runs only; an E2E stage past `-E2eTimeoutMinutes` (default 10) is killed as a hang, keeping the process table and, with `dotnet-dump` installed, dumps) |
| API types after a host change | `pwsh scripts/api-types.ps1`: writes the host's OpenAPI document to `src/app/api/openapi.json` from the in-proc E2E host (no host to run, no Workspace touched), then `bun run api:types` regenerates `schema.d.ts` from it; fix what `bun run typecheck` points at and commit both files. The gate regenerates both anyway ([ADR 0017](../adr/0017-openapi-document-is-the-http-contract.md)) |
| A new icon | add the name to the `IconName` union in `ui/icons.ts`, `bun run icons` (network), commit the font and `icons.manifest.json`; `icons:check` fails the gate offline when they drift |
| Drive it by hand | `tools/browse` ([README](../../tools/browse/README.md)) or the `verify` skill |

The .NET solution never builds the web project: `dotnet build` and the unit tests need no Bun, and without a bundle `/app` serves a "run the build" page and every browser test skips.

## Conventions

1. **Light DOM + `@scope`.** Component CSS is `@scope (tag) to (child-tag) { … }`; tokens and global primitives live in `global.css`. Elements are `r2m-*` (the root is `app-root`), and the `r2m-` BEM classes and `data-*` attributes are the stable E2E hooks.
2. **CSS is imported as text and adopted** through `adoptStyles()`. Never `import './x.css'`: Bun leaves it unlinked in lazy chunks in production builds, and the dev server hides the bug.
3. **Services.** `use(X)` builds or finds an app-wide service; `provide(host, X, instance)` gives a service page scope through DOM ancestry; a class whose constructor takes arguments (`BookStore(projectStore)`) can only be reached that way, since `use()` refuses to build it; `token()` names a service that is not a class (`LIVE_CONNECTION_FACTORY`). Tests use `override()` and `resetServices()`.
4. **Router** (`core/router.ts` + `<r2m-outlet>`): Navigation API + URLPattern, a nested route table with a lazy `load()` per level, signals for params, query and match, breadcrumb titles from the route chain. Links and `Router.navigate()` take app-relative paths (`projects/x/book`) resolved against `<base href>`. `guardUnsaved` cancels the navigation, confirms, then repeats it (`traverseTo` for back/forward); `beforeunload` covers closing the tab. A route with a `title` and no `tag` (`projects`, `settings`) groups its children and takes no outlet level; an index child (`path: ''`) names the page (tab title) but adds no crumb, since it shares its parent's path. A title may be a function of the params that reads a signal (the project crumb reads `ProjectTitles`), and the tab title follows it.
5. **Elements** extend `R2mElement`: `template()` returns lit-html; one effect per element, renders coalesced per microtask; `effect()` and `onDisconnect()` tied to connection; `updated()` is the after-render hook; `await el.rendered()` resolves after the next render. Inputs are getter/setter pairs over a private signal. Outputs are DOM events from `emit()` (`r2m-*` or kebab-case), bubbling only when a parent listens up the tree. Presentational markup without state is a function returning a template, not an element. Register with `define()` and import element modules for their side effect. Don't name a member after an `HTMLElement` member (`remove`, `focus`, `hidden`, `title`, `click`).
6. **Overlays.** Dialogs: `openDialog(el, options?)` over native `<dialog>`, the content emits `r2m-close`; `{ variant: 'sheet' }` docks it to the bottom edge, `{ variant: 'fullscreen' }` fills the viewport (Edit with AI) and `{ closedBy: 'none' }` turns off light dismiss and Escape. Menus: `popover` + implicit-anchor positioning for a menu with one invoker; a menu shared by many triggers (the node menu, the tooltip) is anchored by an explicit `anchor-name` set on the current trigger. Tooltips: a `data-tooltip` attribute and one shared anchored popover. Select: native `<select>`. The preflight bottom sheet is `openDialog(sheet, { variant: 'sheet', closedBy: 'none' })`.
7. **Virtual scroll is `<r2m-measured-list>`** over the unchanged `HeightIndex`: `key` and `row` functions, then `items`; `scrollToIndex`, `scrollToOffset`, `offsetOf`, `scrollOffset('top'|'bottom')`; the `r2m-top-row` event. Rows are `display: flow-root`. Key rows on ids, never titles. Rows are partials, not elements: the `row` function runs inside the list's own effect, so a signal it reads (the reader's `RowContext`) re-renders the visible rows and nothing else. Every rendered row is watched by a `ResizeObserver`: a row that changes height after its first measure re-measures alone and the top row stays put.
8. **The structure tree is a flat ARIA tree** written by hand (`r2m-structure-tree`: `flattenTree` lists the visible rows, each a `role=treeitem` with `aria-level`/`aria-setsize`/`aria-posinset`/`aria-expanded`, a roving tabindex and the WAI-ARIA tree keys, type-ahead debounced 200 ms); the caller controls expansion (`expanded-change` → `BookStore.setExpanded`). The roving helper (`ui/roving.ts`: `rovingTarget` is the pure key→index rule, `rovingKeydown` moves focus and the single tab stop, `typeAheadTarget` + `TypeAhead` collect letters and find the next match) is shared with the node menu and `tabs()`. **Per-node menus are one shared `r2m-node-menu`** (spec §7, risk 2): a trigger dispatches a bubbling `r2m-node-menu-open`, ancestors on the way (the tree) may fill in `returnTo` and `onAction`, and the menu's parent is its scope. It re-anchors its popover to each open's trigger through an explicit `anchor-name`, so a receipt re-render under it keeps the anchor (lit `repeat` keeps the trigger by id); its keys never reach the tree because the panel lives outside it; Escape and a chosen entry return focus to `returnTo`.
9. **Mutations**: send the command, ignore the response, let the `receipt` drive the reload. That includes showing what this tab created: when its own receipt (`isOwn`) has a `createdId` among its `paragraphIds`, the receipt plan (`receipt-plan.ts`) rereads `createdParentId`'s chapter in place if it is loaded, or `BookStore` opens and scrolls to it if not (an emptied chapter is usually not in the window). Any command whose receipt names a created paragraph's parent is revealed this way with no extra code (Node insertion today; an inserted pause paragraph does not report one, so it falls back to rereading the visible chapter), and another view's receipt never moves the reader. A new volume, part or chapter is born empty, so its receipt's tree reload is all it gets (a collapsed parent stays collapsed); a created item needs no reveal, because its receipt names its paragraph and rereads it in place. Book edits (split, insert, rename, merge, delete) all go through the node menu's `commandFor` flows and their top-layer dialogs (`PromptService`, `ConfirmService`) into `BookEditor`; a row holds no editing state, so recycling a row can lose nothing (spec §7, risk 1). AI actions are gated by `use(Preflight).ensureReady('<task>')` (`shared/preflight.ts`): a ready plan resolves `true` at once, otherwise the `r2m-preflight-sheet` opens as a bottom sheet and the run over the hub decides. The reader's Attribute actions (the selection bar, the tree's "Attribute unprocessed", through `SelectionWorkflow`) and its audio ones (Generate audio, "Generate audio for this node", Retry, through `AudioGenerator`) are gated; `Tests/Api/PreflightApiTests` covers the host side of the gate.
10. **The activity centre is app-wide.** `ActivityStore` and `AiServicesStore` are created once by `use()` and never disposed: the shell creates `ActivityStore` on boot, and `AiServicesStore` is created on its first `use()` (the open drawer, the AI services page or a managed-service status). The drawer is mounted only while open, and a stream tab element acquires its feed on connect and releases it on disconnect, so `stream:llm` / `stream:audio` are joined exactly while visible.
11. **Specs** run under `bun test` on happy-dom. A spec that needs a real browser (dialog focus, popover, anchor positioning, layout) belongs in E2E: happy-dom has no `showPopover`, and `showModal` only flips `open`. A partial is tested by `render(partial(...), host)` from lit-html; an element by creating it, setting properties, appending and `await el.rendered()`.
12. **Messages to a new user** (`ui/partials.ts`, `ui/menu.ts`). Advice comes before the click, never inside a confirm: an out-of-order action shows its one sentence through `adviceLine` (under the action, above a dialog's own button) or a menu entry's `hint`. A long-lived disabled control carries a **blocked reason** through `blockable`; the reason is a pure `xBlockedReason(gate): string | null` in the feature folder's logic file (`editor-logic.ts`'s `applyBlockedReason`), never in `ui/`, tested by a table spec. The Book page's book writes share one edit gate instead: `BookEditor.blocked(local?)` answers `Block | null` (`{ reason: null }` blocks without a reason, e.g. while saving) over the pure `blockedReason` in `api/step-view.ts` (viewing a step > stale > the caller's local reason > none), and `BookEditor` declines a write on the same answer. A momentary busy carries no reason: the Book toolbar shows one busy `statusChip` "Saving…" (`data-testid=book-saving`) in the toolbar, before the actions menu, while `BookEditor.saving` holds (the stale banner covers staleness). A **callout** comes from one pure `xCallout(input): Callout | null` in the stage's feature folder, called by both its Overview row and its page. Errors stay toasts. A setting a step needs is named in prose in the blocked reason, plus a callout with an `href` action where a link matters. A **permanent-change confirm** (`ui/dialogs.ts`) guards a button or menu entry whose change one more action cannot reverse: a pure builder in the feature folder returns `PermanentChange { action, scope, cost, destructive } | null` (null when this call loses nothing), `confirmPermanent(change)` asks through `ConfirmService` ("Action?", scope then cost, the verb on the button) and resolves true at once for null; a flow that takes injected dialogs (the node menu's `commandFor`) maps with `permanentConfirmOptions`. Red (`destructive`) only when the scope deletes, discards or replaces something the user made or waited for. The Book page's builders are `pages/book/permanent-changes.ts` (Add pauses always, node Merge always, item Merge red, selection Attribute only when an assigned dialog speaker would be replaced, Generate audio and the speaker chip only when audio would go; the selection ones count over the selected rows, reading chapters outside the window first). The rest of the sweep lives in a `permanent-changes.ts` per feature folder: `activity/` (job Cancel always, neutral, asked inside `ActivityStore.cancel` so the pill and the card share it), `pages/settings/llm/` (chain Remove step always, red), `pages/project/` (Remove cover always, red; `rereadConfirm(checkpoints)` is the Reread confirm both the Overview row and the Book overflow show, naming the confirmed and skipped steps it clears when any checkpoint row exists) and `pages/cast/voices/` (Send to AI only over an existing transcript, red). A dialog the user filled in is its own confirm (Reread with split rules: red submit, body names what goes; Add titles); each builder has a table spec.

## Rules the lint enforces

oxlint's type-aware rules plus `eslint-plugin-lit` on templates; no `fetch` outside `api/` (HTTP goes through `ApiClient`); TypeScript `strict` + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`.

## Adding a page

1. Create `pages/<area>/<name>-page.ts`: a class extending `R2mElement`, registered with `define('r2m-<name>-page', …)`, its CSS in a sibling `.css` imported as text and passed to `adoptStyles()`. Read through a per-area `*Api` in `api/` (add one if the area has none) and reach shared services with `use(X)`; for anything that changes over time, listen through `LiveService` rather than polling.
2. Add the route to the table in `app.routes.ts`: `path`, `title`, `tag` and a lazy `load: () => import('@app/pages/<area>/<name>-page')`; set `guardUnsaved: true` and implement `hasUnsavedChanges()` if the page holds edits. Project-scoped pages sit under `projects/:folder` so `r2m-project-shell` joins the project group for them; the section and crumbs come from `route-meta.ts`'s `shellContext()`.
3. Build the view from the primitives in the catalogue below. A missing building block goes into `ui/` (CSS on a native control, a partial, or an element, by the rule above the catalogue) with a row in the catalogue, not into the page.
4. Gate any AI action with `await use(Preflight).ensureReady('<task>')`; the task kinds are `attribution`, `audio`, `voicePrompt`, `discovery`, `voiceDesign`, `transcription`, `bookEdit`. A queue button goes through `enqueueWithPreflight` (`shared/enqueue.ts`) instead, which runs the gate and toasts the count.
5. Mutations: send the command, do nothing with the response, and let the receipt drive the reload. Hand a failed call's `ApiError` to `ToastService.problem()`.
6. Tests: an element spec beside the page (`bun test`, happy-dom, `FakeApi`/`FakeLive`) for state, rendering and the requests it sends, and an API test (`src/Read2Me.E2eTests/Tests/Api`) or a .NET unit test for the host side. Don't add a browser test for the round trip: see Browser tests for the few things only a browser proves.

A PR that adds a primitive adds its row. The look is M3-flavoured: pill buttons, outlined fields with the label stacked above (not floating), density −1, no ripple.

## Browser tests

Keep them to a minimum; the aim is none. A browser test earns its place only when nothing cheaper can prove the behaviour: real layout and scrolling (happy-dom has no layout), the real top layer (popover anchoring, focus through a real modal), or the bundle's SignalR client against the real hub. A flow whose layers each have a cheaper test does not get one: a web spec over `FakeApi`/`FakeLive` covers the web side, an API or unit test covers the host side, and the regenerated contract (`openapi.json` → `schema.d.ts`, then typecheck) and `live-messages.spec` catch drift between them. Every browser test runs in both browsers and is the likeliest place for a timing race. On 2026-10-13 the suite was cut from 68 tests to a handful, and each class stays for one of those reasons: `LiveUpdateTests` (a split in one browser reaches another after a forced hub disconnect), `BigBookTests` (a deep link holds its header over prepends; anchoring holds over a resize), `NodeMenuTests` (a menu stays on its trigger while a receipt re-renders the tree, and focus returns through the real confirm), `HistorySheetTests` (the History sheet docks beside the page and covers the page body under 900 px; the viewing banner sits between the app bar and a greyed page where a Reader mode tab and a tree click still work and the edit menus are off), `OverviewLayoutTests` (at phone width the stepper leads, help opens inline under a split head row, and the next-step pill keeps only its main button under 900 px), `RowHighlightTests` (a row's hover highlight holds while pointer and focus are in its open menu's top-layer popover; computed styles need a real engine) and `PronunciationMarksTests` (the Book view's hover card is a top-layer popover over the reader under its mark, and a Pronunciation saved elsewhere marks an open Book view over the real hub) and `PronunciationPanelTests` (the panel is a third column on a wide page and floats over the reader's right edge on a narrow one).

`E2eTestBase` (in `src/Read2Me.E2eTests/Infrastructure`) copies the built bundle into the in-proc host's web root; `GotoAppAsync("projects/x/book")` adds the `/app` prefix and waits until the shell reports the live hub connected (`data-live-state="connected"` on `app-root`, so a transport fallback still counts), and `AppPath(...)` builds the expected URL. `R2M_E2E_BROWSER=chromium|firefox` picks the browser, and every class runs in both. Each test class gets its own host, an `E2eAppFixture` class fixture (`E2eTestBase` declares it; an API or host class adds `IClassFixture<E2eAppFixture>` itself): `FakeAi` (LLM/TTS/whisper replies), `FakeControl` (container statuses, op log), `Encoder` (fake ffmpeg), the seeders (`SeedProjectAsync`, `SeedThreeDialogParagraphProjectAsync`, …) and `WaitForQueueDrainAsync`. Classes run in parallel and share only the browser (`PlaywrightFixture`); don't put a class in a `[Collection]`, which would serialize it and share its host again. Tests inside a class run in order on that host, so host state a test changes (a shut-down fake service, a theme selection, an active config) must still be restored in a `finally` for the class's next test; the fakes are reset before every browser test.

Classes in parallel make every browser slow at times (a single Firefox click can take seconds), so a test waits on a signal, never on time. To catch work in flight, hold it rather than slow it: `FakeAi.HoldLlmAfter(n)` answers `n` completions and holds the rest until their request is cancelled or `FakeAi.ReleaseLlm()`, which a fixed delay would only make likely. Watch for something short-lived (a 3 s toast) from before the action that causes it (`locator.WaitForAsync()` started early, awaited at the end), and press keys that must land together (type-ahead's 200 ms window) in one in-page burst rather than with `Keyboard.TypeAsync`, which waits a round trip per key. An API test that opens the live hub with a `HubConnection` and expects a push before it invokes any hub method starts it with `StartJoinedAsync()`: `StartAsync` returns before the hub has joined the connection to its groups, so a push right after it can be lost (a hub invocation such as `JoinProject` is the same round trip).

One file per area under `Tests/Web`, named for what it proves. Locate by `r2m-*` element or BEM class, `data-action` / `data-entry` / `data-testid`, or ARIA roles and labels. Partials put their name on their root as a class (`.r2m-job-pill`), drawer tabs are `GetByRole(AriaRole.Tab, new() { Name = "LLM" })`, the preflight sheet sits inside `GetByRole(AriaRole.Dialog)`, and a select is a native `<select>`: locate it with `GetByRole(AriaRole.Combobox)`, pick with `SelectOptionAsync(new SelectOptionValue { Label = "…" })`, and read its choices from `option:not([disabled])` (a placeholder option is disabled and hidden). An expansion panel opens by clicking its `summary` (`card.Locator("[data-section='advanced'] > summary")`), and an element that marks `aria-busy="true"` during a write is awaited with `Expect(card).Not.ToHaveAttributeAsync("aria-busy", "true")` before the next assertion. A popover menu's `role=menu` carries the same `aria-label` as the button that opens it, so locate the trigger by role (`GetByRole(AriaRole.Button, new() { Name = "Actions for x" })`, not `[aria-label=…]`) and its entries as `GetByRole(AriaRole.Menuitem, …)`; a toggle is a checkbox `role=switch`, asserted with `ToBeCheckedAsync()`. A test that needs background work queues it through the agent API (`…/attribution/enqueue-paragraphs`), not through the UI.

## Gotchas

- Import CSS as text and use `adoptStyles()`. A plain CSS import breaks in production lazy chunks.
- Import elements for their side effect; a type-only import never registers the element.
- lit's `repeat` runs its item template at commit time, outside the element's render effect, so a signal first read *inside* that item template (a store's busy flag, the selected id) is not tracked and the list never re-renders for it. Read the signals in `template()` and hand the item template plain values (the services and themes pages derive a card record per item, then `repeat` over those).
- In a spec, mount an element that contains an `<r2m-outlet>` (the project shell) through a root outlet, as the app does. Appended straight to `body`, its own outlet counts as level 0 and renders the element again inside itself.
- `theme-css.ts` writes the whole §5.1 token set (including `--r2m-accent-container`, `--r2m-secondary*`, `--r2m-surface-highest`) and `global.css` carries a `light-dark()` fallback for each, so a token resolves with or without a host theme. A new token needs both: the mapping and the fallback.
- Element member names collide with `HTMLElement`'s (`remove`, `focus`, `hidden`, `title`, `click`).
- Restart `bun run dev` after adding a file reached through `@app/*`.
- Measured-list rows must be `flow-root`. Key rows on ids, never titles. Never `content-visibility: auto` alone.
- Headless Firefox reports `pointer: none` by default, so a menu that focuses its search only for `(pointer: fine)` never does there. `PlaywrightFixture` sets `ui.primaryPointerCapabilities` / `ui.allPointerCapabilities` to a fine, hovering pointer for Firefox, as a real desktop Firefox reports, so the app behaves as on the user's machine and `ToBeFocused` on the search holds in both browsers.
- `navigate` events for back/forward are cancelable in both browsers; in Chromium that needs user activation.
- Bun 1.4.2 on Windows: `rmSync` throws `EINVAL` for a relative path through `..`, existing or not (resolve it first), and `Bun.build` won't create its `outdir`.
- Computed lists are synchronous, so Enter-before-render races are gone. Don't reintroduce async list derivation.
