# Web conventions

1. **Light DOM + `@scope`.** Component CSS is `@scope (tag) to (child-tag) { … }`; tokens and global primitives live in `global.css`. Elements are `r2m-*` (the root is `app-root`), and the `r2m-` BEM classes and `data-*` attributes are the stable E2E hooks.
2. **CSS is imported as text and adopted** through `adoptStyles()`. Never `import './x.css'`: Bun leaves it unlinked in lazy chunks in production builds, and the dev server hides the bug.
3. **Services.** `use(X)` builds or finds an app-wide service; `provide(host, X, instance)` gives a service page scope through DOM ancestry; a class whose constructor takes arguments (`BookStore(projectStore)`) can only be reached that way, since `use()` refuses to build it; `token()` names a service that is not a class (`LIVE_CONNECTION_FACTORY`). Tests use `override()` and `resetServices()`.
4. **Router** (`core/router.ts` + `<r2m-outlet>`): Navigation API + URLPattern, a nested route table with a lazy `load()` per level, signals for params, query and match, breadcrumb titles from the route chain. Links and `Router.navigate()` take app-relative paths (`projects/x/book`) resolved against `<base href>`. `Router.replaceQuery(patch)` changes the current page's query in place (replace history, other keys kept). A link to the Book page is built with `bookLink` and its query read with `parseBookAddress` (`pages/book/book-address.ts`, the Book address), never as loose literals. `guardUnsaved` cancels the navigation, confirms, then repeats it (`traverseTo` for back/forward); `beforeunload` covers closing the tab. A route with a `title` and no `tag` (`projects`, `settings`) groups its children and takes no outlet level; an index child (`path: ''`) names the page (tab title) but adds no crumb, since it shares its parent's path. A title may be a function of the params that reads a signal (the project crumb reads `ProjectTitles`), and the tab title follows it.
5. **Elements** extend `R2mElement`: `template()` returns lit-html; one effect per element, renders coalesced per microtask; `effect()` and `onDisconnect()` tied to connection; `updated()` is the after-render hook; `await el.rendered()` resolves after the next render. Inputs are getter/setter pairs over a private signal. Outputs are DOM events from `emit()` (`r2m-*` or kebab-case), bubbling only when a parent listens up the tree. Presentational markup without state is a function returning a template, not an element. Register with `define()` and import element modules for their side effect. Don't name a member after an `HTMLElement` member (`remove`, `focus`, `hidden`, `title`, `click`).
6. **Overlays.** Dialogs: `openDialog(el, options?)` over native `<dialog>`, the content emits `r2m-close`; `{ variant: 'sheet' }` docks it to the bottom edge, `{ variant: 'fullscreen' }` fills the viewport (Edit with AI) and `{ closedBy: 'none' }` turns off light dismiss and Escape (`'closerequest'` keeps Escape only). A dialog that holds unsaved work implements `canClose()`, so Escape, the backdrop and its Cancel (`requestDialogClose(this)`) ask before throwing it away; every dialog is named by its `.r2m-dialog__title`, or `{ ariaLabel }` when it has none ([primitives.md](primitives.md), Dialog). A dialog with fields is a **form dialog**: its fields and actions sit in a `<form novalidate @submit>` that calls `preventDefault()`, the primary button is `type="submit"` (Cancel `type="button"`) and is disabled only while busy (`?disabled=${busy}`), never because the draft is invalid. Submit touches every field; an invalid draft shows every error, focuses the first invalid field in reading order (a file drop's is its Choose file button) and sends nothing. A field is touched on `blur` (a select or a file drop on `change`), never on `input`, so no error shows while the user types; a touched field's error still clears on the `input` that fixes it. A shown error is its control's `aria-describedby` and sets `aria-invalid="true"` (`"false"` otherwise, never unset); it is not a live region, and `announceError()` says it once after the blur or change that brought it up ([primitives.md](primitives.md), Field partial) (New project, Theme editor, Text prompt, Add voice rule). Menus: `popover` + implicit-anchor positioning for a menu with one invoker; a menu shared by many triggers (the node menu, the tooltip) is anchored by an explicit `anchor-name` set on the current trigger. A `role="menu"` popover implements the menu keyboard with `menuKeys` (`ui/menu.ts`), or drops the menu roles: the roles without the keys strand a screen reader user. Tooltips: a `data-tooltip` attribute and one shared anchored popover; a tip that says more than the trigger's accessible name also goes through `withTip`, which makes it the trigger's description (`data-tooltip-overflow` and `data-tooltip-delegate` opt-ins: [primitives.md](primitives.md)). Select: native `<select>`. The preflight bottom sheet is `openDialog(sheet, { variant: 'sheet', closedBy: 'none' })`. An overlay that is neither a dialog nor a popover (the narrow-screen nav drawer) handles its own modality: Escape, `inert` on everything else, focus in on open and back to the trigger on close, and `aria-expanded` on the trigger ([primitives.md](primitives.md), Navigation drawer).
7. **Virtual scroll is `<r2m-measured-list>`** over the unchanged `HeightIndex`: `key` and `row` functions, then `items`; `scrollToIndex`, `scrollToOffset`, `offsetOf`, `scrollOffset('top'|'bottom')`; the `r2m-top-row` event. Rows are `display: flow-root`. Key rows on ids, never titles. Rows are partials, not elements: the `row` function runs inside the list's own effect, so a signal it reads (the reader's `RowContext`) re-renders the visible rows and nothing else. Every rendered row is watched by a `ResizeObserver`: a row that changes height after its first measure re-measures alone and the top row stays put.
8. **The structure tree is a flat ARIA tree** written by hand (`r2m-structure-tree`: `flattenTree` lists the visible rows, each a `role=treeitem` with `aria-level`/`aria-setsize`/`aria-posinset`/`aria-expanded`, a roving tabindex and the WAI-ARIA tree keys, type-ahead debounced 200 ms); the caller controls expansion (`expanded-change` → `BookStore.setExpanded`). The roving helper (`ui/roving.ts`: `rovingTarget` is the pure key→index rule, `rovingKeydown` moves focus and the single tab stop, `typeAheadTarget` + `TypeAhead` collect letters and find the next match) is shared with the node menu and `tabs()`. A focused row draws its ring as an inset `box-shadow` plus a `2px solid transparent` outline, since forced colours drop the shadow but paint the outline. **Per-node menus are one shared `r2m-node-menu`** (spec §7, risk 2): a trigger dispatches a bubbling `r2m-node-menu-open`, ancestors on the way (the tree) may fill in `returnTo` and `onAction`, and the menu's parent is its scope. It re-anchors its popover to each open's trigger through an explicit `anchor-name`, so a receipt re-render under it keeps the anchor (lit `repeat` keeps the trigger by id); its keys never reach the tree because the panel lives outside it; Escape and a chosen entry return focus to `returnTo`.
9. **Mutations**: send the command, ignore the response, let the `receipt` drive the reload. That includes showing what this tab created: when its own receipt (`isOwn`) has a `createdId` among its `paragraphIds`, the receipt plan (`receipt-plan.ts`) rereads `createdParentId`'s chapter in place if it is loaded, or `BookStore` opens and scrolls to it if not (an emptied chapter is usually not in the window). Any command whose receipt names a created paragraph's parent is revealed this way with no extra code (Node insertion today; an inserted pause paragraph does not report one, so it falls back to rereading the visible chapter), and another view's receipt never moves the reader. A new volume, part or chapter is born empty, so its receipt's tree reload is all it gets (a collapsed parent stays collapsed); a created item needs no reveal, because its receipt names its paragraph and rereads it in place. Book edits (split, insert, rename, merge, delete) all go through the node menu's `commandFor` flows and their top-layer dialogs (`PromptService`, `ConfirmService`) into `BookEditor`; a row holds no editing state, so recycling a row can lose nothing (spec §7, risk 1). AI actions are gated by `use(Preflight).ensureReady('<task>')` (`shared/preflight.ts`): a ready plan resolves `true` at once, otherwise the `r2m-preflight-sheet` opens as a bottom sheet and the run over the hub decides. The reader's Attribute actions (the selection bar, the tree's "Attribute unprocessed", through `SelectionWorkflow`) and its audio ones (Generate audio, "Generate audio for this node", Retry, through `AudioGenerator`) are gated; `Tests/Api/PreflightApiTests` covers the host side of the gate.
10. **The activity centre is app-wide.** `ActivityStore` and `AiServicesStore` are created once by `use()` and never disposed: the shell creates `ActivityStore` on boot, and `AiServicesStore` is created on its first `use()` (the open drawer, the AI services page or a managed-service status). The drawer is mounted only while open, and a stream tab element acquires its feed on connect and releases it on disconnect, so `stream:llm` / `stream:audio` are joined exactly while visible.
11. **Specs** run under `bun test` on happy-dom. A spec that needs a real browser (dialog focus, popover, anchor positioning, layout) belongs in E2E: happy-dom has no `showPopover`, and `showModal` only flips `open`. A partial is tested by `render(partial(...), host)` from lit-html; an element by creating it, setting properties, appending and `await el.rendered()`.

12. **Messages to a new user**: see [user-messages.md](user-messages.md).
13. **Screen reader announcements** go through `announce()` (`ui/announcer.ts`), never a live region of your own; `assertive` only for data loss, a lost connection or failures. The `role=status` / `alert` nodes already in the app predate it: don't copy them ([primitives.md](primitives.md), Announcer).

## Adding a page

1. Create `pages/<area>/<name>-page.ts`: a class extending `R2mElement`, registered with `define('r2m-<name>-page', …)`, its CSS in a sibling `.css` imported as text and passed to `adoptStyles()`. Read through a per-area `*Api` in `api/` (add one if the area has none) and reach shared services with `use(X)`; for anything that changes over time, listen through `LiveService` rather than polling; project data is followed through `ProjectFeed` (`refetchOn` for a plain refetch).
2. Add the route to the table in `app.routes.ts`: `path`, `title`, `tag` and a lazy `load: () => import('@app/pages/<area>/<name>-page')`; set `guardUnsaved: true` and implement `hasUnsavedChanges()` if the page holds edits. Project-scoped pages sit under `projects/:folder` so `r2m-project-shell` joins the project group for them; the section and crumbs come from `route-meta.ts`'s `shellContext()`.
3. Build the view from the primitives in [primitives.md](primitives.md). A missing building block goes into `ui/` (CSS on a native control, a partial, or an element, by the rule at the top of that file) with a row in the catalogue, not into the page.
4. Gate any AI action with `await use(Preflight).ensureReady('<task>')`; the task kinds are `attribution`, `audio`, `voicePrompt`, `discovery`, `voiceDesign`, `transcription`, `bookEdit`. A queue button goes through `enqueueWithPreflight` (`shared/enqueue.ts`) instead, which runs the gate and toasts the count.
5. Mutations: send the command, do nothing with the response, and let the receipt drive the reload. Hand a failed call's `ApiError` to `ToastService.problem()`.
6. Tests: an element spec beside the page (`bun test`, happy-dom, `FakeApi`/`FakeLive`) for state, rendering and the requests it sends, and an API test (`src/Read2Me.E2eTests/Tests/Api`) or a .NET unit test for the host side. Don't add a browser test for the round trip: see [browser-tests.md](browser-tests.md) for the few things only a browser proves.

## Gotchas

- Import CSS as text and use `adoptStyles()`. A plain CSS import breaks in production lazy chunks.
- Import elements for their side effect; a type-only import never registers the element.
- A control revealed in place on hover (the Node menu triggers in the reader and the tree) also shows on `:focus-within`, and is visible at rest under `@media (hover: none)`: nothing hovers on a phone or tablet.
- Inside a scrolling page, `overscroll-behavior: contain` goes only on an element that really scrolls: Chromium and Firefox also apply it to a scroll container with nothing to scroll (`overflow: auto`, content that fits), which then swallows the wheel instead of scrolling the page. Where a region only sometimes overflows, mark it from its element and scope the rule to the mark (`r2m-config-list`'s `data-overflows`). Playwright's Firefox wheel ignores the property, so a Firefox browser run cannot prove it.
- A page's layout breakpoint is `@container page (…)` in `em` (900 px is `56.25em`), never a viewport `@media` width: `.shell__main` is the `page` container, and the rail, the Activity drawer and the History sheet dock beside it. Only the shell's own breakpoint, which is about the viewport, stays `@media`. The query measures `.shell__main`'s content box (inside its padding), and its `em` is the container's font size, not the initial 16 px a media query uses.
- Chrome follows the user's default font size (modern-web-guidance `accessibility/respect-os-text-scale`, `typography`): a text-bearing control or bar takes `min-height` / `min-block-size`, never a fixed `height`, so it grows instead of clipping (the app bar and activity bar keep their 48 px and 40 px as minimums); icons and checkboxes are sized in `rem`, and a viewport `@media` breakpoint in `em` (the shell's `(width < 56.25em)`, matched by `NARROW_QUERY` in `shell.ts`). `rem` rather than `em` for icons, so an icon inside 14 px text keeps its 20 px.
- A spatial transition (movement, size, rotation) sits inside `@media (prefers-reduced-motion: no-preference)`, nested in its rule, so the end state still applies at once under `reduce`; colour, opacity and shadow transitions stay outside (modern-web-guidance `motion`). The voice card chevron (`cast.css`) and the project card's progress fill predate this rule: don't copy them.
- Every pointer target is at least 24 × 24 CSS px (`--r2m-target-min`, WCAG 2.5.8; modern-web-guidance `form-factor-adaptation`). No 44 px rule under `(pointer: coarse)`: this is a dense desktop tool. A smaller target keeps its look and takes `.r2m-hit` ([primitives.md](primitives.md), Hit area), whose area draws no layout and must not overlap a neighbouring target; where a row is too dense for 24 px, the target passes by WCAG's spacing exception (a 24 px circle on its centre touches no other target) or the row gets the room.
- lit's `repeat` runs its item template at commit time, outside the element's render effect, so a signal first read *inside* that item template (a store's busy flag, the selected id) is not tracked and the list never re-renders for it. Read the signals in `template()` and hand the item template plain values (the services and themes pages derive a card record per item, then `repeat` over those).
- In a spec, mount an element that contains an `<r2m-outlet>` (the project shell) through a root outlet, as the app does. Appended straight to `body`, its own outlet counts as level 0 and renders the element again inside itself.
- `theme-css.ts` writes the whole §5.1 token set (including `--r2m-accent-container`, `--r2m-secondary*`, `--r2m-surface-highest`) and `global.css` carries a `light-dark()` fallback for each, so a token resolves with or without a host theme. A new token needs both: the mapping and the fallback.
- Text on a theme colour (`--r2m-on-accent`, `--r2m-on-secondary`, `--r2m-appbar-fg`, the `--r2m-nav-*` foregrounds, the theme editor's defaults, the themes page swatch label) comes from `contrastText(hex)` in `theme-css.ts`: black or white, whichever has the higher WCAG contrast ratio with it (`contrastRatio(a, b)`, exported for contrast checks; modern-web-guidance `visual-design/contrast-color`, `visual-design/color`). Never a luminance threshold: a cut-off above 0.179 hands white text below AA to mid-tones such as `#e67e22`. It stays in TS, not native `contrast-color()`, because the editor needs the value.
- Control boundaries use `--r2m-outline` (M3 *outline*, at least 3:1 on every built-in surface): a field, stroked button, segmented edge, switch track, range track, menu, picker, drop zone, chip, swatch or step marker, or a state shown by an edge. Dividers use `--r2m-outline-variant` (M3 *outline-variant*): the `border-top` / `border-bottom` / side rules between sections and panes, table rules, `label + label`, and the edge of a non-interactive card or panel (modern-web-guidance `visual-design/color`, `visual-design/browser-ui-theming`). Themes override neither.
- A filter bar (the search box and any sort or filter beside it) is a `<search>` landmark named `Filter <things>` (`aria-label`), so landmark navigation reaches it; an Add or New button beside it stays outside. `<search>` is `display: block`, so when it wraps a flex item, move that item's `flex` and `min-width` onto it. A sort that reorders the list announces its result once through `announce()` on each change (wording: [user-messages.md](user-messages.md), Announcements), and compares text with one module-level `Intl.Collator(undefined, { numeric: true, sensitivity: 'base' })`, so "Guard 2" comes before "Guard 10" (the Cast roster, `cast-rows.ts`). The `localeCompare` sorts elsewhere predate this rule: don't copy them.
- Element member names collide with `HTMLElement`'s (`remove`, `focus`, `hidden`, `title`, `click`).
- Restart `bun run dev` after adding a file reached through `@app/*`.
- Measured-list rows must be `flow-root`. Key rows on ids, never titles. Never `content-visibility: auto` alone.
- Headless Firefox reports `pointer: none` by default, so a menu that focuses its search only for `(pointer: fine)` never does there. `PlaywrightFixture` sets `ui.primaryPointerCapabilities` / `ui.allPointerCapabilities` to a fine, hovering pointer for Firefox, as a real desktop Firefox reports, so the app behaves as on the user's machine and `ToBeFocused` on the search holds in both browsers.
- `navigate` events for back/forward are cancelable in both browsers; in Chromium that needs user activation.
- Bun 1.4.2 on Windows: `rmSync` throws `EINVAL` for a relative path through `..`, existing or not (resolve it first), and `Bun.build` won't create its `outdir`.
- Computed lists are synchronous, so Enter-before-render races are gone. Don't reintroduce async list derivation.
- A custom `keydown` handler that acts on Enter or Escape returns early on `isComposing(e)` (`ui/keys.ts`): mid IME composition Enter confirms a conversion and Escape cancels one (modern-web-guidance `forms/ime-safe-enter-submit`). A `<form>` whose Enter submits natively needs no handler at all.
