# Primitive catalogue

The shared building blocks in `ui/` (and the `core/` and `help/` pieces pages build with). Feature elements are not listed: read their own file under `pages/<area>/`.

The rule for a new primitive: CSS on a native control by default; a partial (function returning a template) only when it wires ARIA or ids; an element only when it owns state or lifecycle. A PR that adds a primitive adds its row. The look is M3-flavoured: pill buttons, outlined fields with the label stacked above (not floating), density −1, no ripple.

| Primitive | Form | Usage |
|---|---|---|
| Icon | partial | `icon(name, cls?)` — `name` is an `IconName`; the committed font is a subset of exactly those names |
| Status chip | partial | `statusChip({ status, label, icon?, tooltip?, compact? })` — `status` is `ok`/`warn`/`error`/`info`/`busy`/`neutral`; colour + icon + text, never colour alone |
| Empty state | partial | `emptyState({ icon, headline, hint?, compact? }, actions?)` — at most two `EmptyStateAction`s, `{ label, icon?, run }` (an in-place command, a button) or `{ label, icon?, href }` (lives elsewhere, a link button); the first is filled, each is `.r2m-empty-state__action`. The label is the real control's exact button label |
| Blockable | partial | `blockable(reason, control, { tabbable? })` — a `.r2m-blockable` `data-tooltip` wrapper that takes `tabindex="0"` only while `reason` is non-null (never with `tabbable: false`, for a control the caller keeps out of the tab order, as a tree node's Node menu trigger), so a disabled control's blocked reason is reachable by hover, tap and keyboard; the control still sets `?disabled=${reason !== null}` itself (the voice editor's Apply) |
| Callout | partial | `callout({ kind, text, action? })` — `kind` is `info`/`warn`; a `.r2m-callout` banner with no dismiss and at most one `MessageAction` (`.r2m-callout__action`) |
| Advice line | partial | `adviceLine(text \| null)` — a muted `<p class="r2m-advice">`, or nothing |
| Help text | partial | `helpText(step, { title? })` (`help/help.ts`, not `ui/`: it is bound to the generated help module) — a `<section class="r2m-help" data-step=…>` with the step's title as its labelled `<h2>` (`title: false` leaves the heading to the host) and the build-rendered body (`## How` → `<h3>`) through `unsafeHTML`; shown through the Overview's `helpPanel(step, onClose, placement)` (`pages/project/help-panel.ts`: icon + name, close ×, the body, an "Open the guide" link to `docs/guide/<step>.md` on GitHub) only |
| Count badge | partial | `countBadge(kind, count, tooltip, showZero?)` — `kind` is `attribution`/`audio`/`review`; renders nothing at zero unless asked |
| Button | CSS | `<button class="r2m-button">` is the text variant; add `r2m-button--filled`, `--stroked` or `--danger` |
| Icon button | CSS | `<button class="r2m-icon-button">` or an `<a>` with the same class: a 40 px round hit area around one `icon()`, colour inherited from its bar; give it `aria-label` and `data-tooltip` |
| Field | CSS | `.r2m-field` wrapping a `.r2m-field__label` and a native control, then an optional `.r2m-field__hint` or `.r2m-field__error` (which also reddens the control's border); `.r2m-field--inline` for a label beside the control (the `field()` partial in `ui/field.ts` wires `aria-describedby`; see the Field partial row) |
| Checkbox | CSS | native `<input type=checkbox class="r2m-checkbox">` |
| Switch | CSS | `<label class="r2m-switch"><input type=checkbox role=switch> Text</label>`: a track with a knob drawn on the checkbox, `accent` when checked |
| Radio group | CSS | `<fieldset class="r2m-radio-group" role=radiogroup aria-label=…>` of `<label class="r2m-radio"><input type=radio …> Text</label>`; the segmented control is the button-toggle look, not this |
| Page header | CSS | `.r2m-page-header` with `__title` and `__subtitle`, and `__actions` for controls at its end (the themes page's switch + New, the services page's Refresh all) |
| Dialog | core + CSS | `openDialog(el)` wraps `el` in a `<dialog class="r2m-dialog">` and resolves with the `r2m-close` detail; the content uses `.r2m-dialog__title`, `__content` and `__actions`. Content that must not be dismissed for a while (an upload in flight) calls `setDialogClosedBy(this, 'none')`, then `'any'` |
| Menu | CSS | a `[popover].r2m-menu` anchored to its invoker by CSS anchor positioning; the invoker is a `<button popovertarget=…>`, so the browser handles light dismiss, Escape and the top layer (the speaker chip's menu is one). A plain entry is a `<button class="r2m-menu__item">` with an optional leading `icon()` (`--destructive` for a delete); `<hr class="r2m-menu__divider">` separates groups; a choice among several carries `role="menuitemradio"` + `aria-checked` (the shell's theme menu). `menuItem({ label, run, icon?, hint?, action?, destructive?, disabled? })` (`ui/menu.ts`) renders an entry that closes its popover before it runs, `hint` as a muted second line (`.r2m-menu__hint`); `menuHeading(text)` is a non-interactive `.r2m-menu__heading` over a group |
| Select | CSS | a native `<select>`; under `@supports (appearance: base-select)` Chromium styles the picker, Firefox keeps its own |
| Confirm dialog | element + service | `use(ConfirmService).confirm({ … })` → `boolean`; renders `<r2m-confirm-dialog>` with `.r2m-confirm-dialog__confirm` |
| Permanent-change confirm | function | `confirmPermanent(change: PermanentChange \| null)` → `boolean` (true at once for null); `permanentConfirmOptions(change)` is the pure mapping onto `ConfirmOptions` (conventions 12) |
| Text prompt dialog | element + service | `use(PromptService).text({ … })` → `string` or `null`; renders `<r2m-text-prompt-dialog>` with `__input` / `__confirm` |
| Toast | service | `use(ToastService).success/info/warn/error(message)` and `.problem(problemDetails)`; `.info(message, actions)` adds `.r2m-toast__action` buttons (`{ label, run }`, each dismisses the toast) and keeps it up 12 s; stack is `.r2m-toasts`, each toast `.r2m-toast--<severity>` |
| Tooltip | CSS + one installer | put `data-tooltip="…"` on the element; `installTooltips()` runs once from `main.ts` and owns the single `.r2m-tooltip` popover. Add `data-tooltip-overflow` to show it only when the element's text is cut off at show time (`scrollWidth > clientWidth`, measured per hover or focus), and `data-tooltip-delegate="<selector>"` on a focusable element with no tip of its own to show its descendant's tip on focus (the structure tree's rows and `.tree__title`) |
| Measured list | element | `<r2m-measured-list>` — set `key`, `row`, then `items`; emits `r2m-top-row`; `scrollToIndex` / `scrollToOffset` / `offsetOf` / `scrollOffset`; rows are `flow-root`, keyed on ids, re-measured one by one through a `ResizeObserver` |
| Segmented control | CSS | `<fieldset class="r2m-segmented" role="radiogroup" aria-label=…>` of `<label><input type=radio …> Text</label>`; locate the group by role and click a label by text |
| Speaker chip | element | `<r2m-speaker-chip>` with `name`, `characterId`, `state` (`named`/`unknown`/`mixed`/`narration`/`narrator-linked`), `roster`, `compact`; with a `roster` it is a `button` that hosts the menu (search focused on open unless the pointer is coarse) and re-emits its events |
| Speaker menu | element | `<r2m-speaker-menu>` with `roster`, `selectedId`, `allowClear`, `allowCreate`; emits bubbling `pick`, `clear`, `create` |
| Outlet | element | `<r2m-outlet>` renders the matched route (core, not `ui/`) |
| Spinner | partial | `spinner(size?, cls?)` — an indeterminate `role=progressbar` ring in `currentColor` |
| Progress bar | CSS | a native `<progress max="1" value=…>`; omit `value` for the indeterminate sweep |
| Placeholder title | CSS | `.r2m-placeholder-title` (muted italic) on the element showing an untitled node's **Placeholder title**; `placeholderTitleClass(nodeTitle)` from `pages/book/book-tree` picks it from `untitled`, never from the label text. The tree's `.tree__title` and the Book page's `.book__volume` / `.book__part` / `.book__chapter` headings carry it |
| Tabs | partial | `tabs({ id, tabs, selected, onSelect, label? })` renders a `role=tablist` of `role=tab` buttons (`data-tab`, `aria-selected`, `aria-controls`) with automatic activation over the roving helper; `tabPanel(id, tab, content)` is the matching `role=tabpanel`. Locate a tab by role and name |
| Bottom sheet | core + CSS | `openDialog(el, { variant: 'sheet', closedBy: 'none' })`: the dialog gets `r2m-dialog--sheet` and docks to the bottom edge |
| Full-screen dialog | core + CSS | `openDialog(el, { variant: 'fullscreen' })`: the dialog gets `r2m-dialog--fullscreen` and fills the viewport |
| Job pill | partial | `jobPill({ job, onOpen, onCancel, tooltip? })` — `.r2m-job-pill` with `__main` (opens the drawer) and `__cancel`; `job` is a `JobView` (`ui/job.ts`: `formatDuration`, `jobSummary`, `JOB_ICONS`) |
| Job card | partial | `jobCard({ job, history?, onCancel, onDismiss })` — `.r2m-job-card` with the numbers `<dl>`, a `<progress>`, an optional sparkline and the Cancel / Dismiss footer |
| Throughput | partial | `throughput(snapshot)` — headline, sparkline and the per-config `.r2m-throughput__table` once the run ended; `sparkline({ values, width?, height?, stroke?, label? })` on its own |
| Docker controls | partial | `dockerControls({ status, busy?, statusOnly?, serviceName?, onStart?, onRestart?, onShutdown?, onRefresh })` — the status chip plus Start / Restart / Shutdown / Refresh icon buttons (by `aria-label`); `SERVICE_STATUS_VIEW` maps `AiServiceStatus` to chip kind + label |
| LLM stream | element | `<r2m-stream-llm>` with `events` (`LlmStreamEvent[]`) and `maxTurns`; folds turns with `ui/llm-turns.ts`, autoscroll pauses on scroll-up (`paused`, "Jump to latest") |
| Audio stream | element | `<r2m-stream-audio>` with `events` (`AudioGenEvent[]`) and `maxCards`; folds cards with `ui/audio-cards.ts`, same autoscroll |
| Preflight sheet | element | `<r2m-preflight-sheet>` with `data: { kind, label, plan }`; owns the plan → running → done/failed phases and the `/run` call, emits `r2m-close` with `true`/`false`. Opened only by `Preflight.ensureReady` |
| Audio player | element | `<r2m-audio-player>` with `src`, `cacheKey` (the `?v=` buster), `label`, `compact`, and `srcB` / `labelA` / `labelB` for the A/B variant; `.r2m-audio-player__toggle` (Play/Pause by `aria-label`), `__scrub`, `__time`, `__error`; emits `playback-ended` and `ab`. `formatClock` is exported. `workspaceUrl(folder, file, version?)` in `api/` builds the `/workspace/…` source |
| File drop | element | `<r2m-file-drop>` with `accept` (native syntax: extensions and/or MIME types), `maxBytes`, `multiple`, `label`, `hint`, `readOnly` (a reason or null: the "Choose file" button is off in a `blockable` with it, a drag is refused and a drop ignored, and the zone takes `r2m-file-drop--read-only`); a dashed drop zone with a "Choose file" button; emits `files` (`File[]`) and `rejected` (`RejectedFile[]`, reason `type` or `size`). The hidden picker keeps `.r2m-file-drop__input` so a browser test can `SetInputFiles` on it |
| Inline edit | element | `<r2m-inline-edit>` with `value`, `placeholder`, `required`, `maxLength`; a `.r2m-inline-edit__display` button that becomes the `.r2m-inline-edit__input` on click (focused and selected). Enter and blur save, Escape cancels; emits `save` only for a changed, valid value, else `cancelled` |
| Splitter | element | `<r2m-splitter>` with `value` (px, the pane before it), `min`, `max`, `defaultValue`, `orientation` (ARIA's: `vertical`, the default, sits between columns and takes `col-resize`; `horizontal` takes `row-resize`) and `label` (its accessible name); the host is a focusable `role=separator` with `aria-valuenow`/`min`/`max` (the value clamped). A captured pointer drag, arrow keys (16 px, Shift 64 px), Home/End (the bounds) and double-click (the default) emit `value-change` with the new clamped value, live and only when it moved; the consumer sets `value` from it. Nothing drawn at rest: a thin accent handle on hover, focus and drag |
| Key/value | partial | `keyValue(rows, { dense? })` — a `<dl class="r2m-key-value">` of `dt`/`dd` pairs; `mono` rows use the monospace stack, a missing value shows an em dash (`__value--empty`) |
| Project card | partial | `projectCard(project, { onOpen, onDelete, deleting?, seriesLine?, badge?, menuEntries?, extra? })` — `.r2m-project-card[data-folder]` with the `__cover` button (workspace image or `placeholderGradient` + `projectInitials`), the `__title` button, the `__more` icon button (`aria-label="Actions for …"`) opening a `role=menu` popover with the `__open` / `__delete` `menuitem`s with `menuEntries` between them, the `__author` line, the `__series` line, the cover's `__badge`, `extra` under the author, and the `__progress` bar or `__unread` |
| Pipeline | partial | `pipeline({ steps, busyAction?, onAct, onCheckpoint?, helpOpen?, onHelp?, renderHelp? })` — an `<ol class="r2m-pipeline">` of `.r2m-pipeline__step[data-step]` rows (`--done`, `--next` + `aria-current="step"`, `--help-open`), each with the `__marker` (number, icon or check) and a body in variant B order: the `__head` (`__title`, `__chip`, the `__checkpoint` group of `[data-checkpoint]` `__pill` buttons + the `__hint` "N later steps already done", a `__spacer`, the `__help-toggle` `?` with `aria-expanded`), the `__help-inline` slot (`renderHelp(step)` while `helpOpen` is this step), `__detail`, the `callout` slot, the `[data-action]` `__action` buttons each wrapped in `blockable` so a disabled one carries its `blockedReason`, and the `adviceLine`; `busyAction` (`step:action` or `step:pill`) spins that button and disables all of them. The nine step rules (state, chip, next marker, `laterDone` hint, `checkpoint` pills, actions with blocked reasons, the row's `advice` line) are the pure `derivePipeline` in `pages/project/pipeline-steps.ts`, beside `adviceFor(action, steps)`; `ProjectStore.pipeline` derives them once for every project page |
| Settings form | element | `<r2m-settings-form>` with `schema` (`SettingsSchema`: `number` / `boolean` / `enum` / `string` / `text` fields), `values`, `mode` (`defaults` edits the full set; `override` edits a sparse patch with the `__dot--on` marker and a `__reset` icon button per overridden field), `disabled`, `readOnly` (a reason or null: every control is off and each field carries it as a focusable `data-tooltip`); native controls (`.r2m-range` + `__number` for a bounded number, a `role=switch`, `__select`, `__text`) located by `aria-label` = the field label; emits `values-change` (full set or sparse patch) and `valid-change`. Pure helpers `effectiveValue`, `sparsePatch`, `isFieldValid` |
| Range | CSS | a native `<input type=range class="r2m-range">`: accent track and thumb, `:focus-visible` ring |
| Expansion panel | CSS | `<details class="r2m-expansion">` with a `<summary>` (an optional `.r2m-expansion__title`) and a `.r2m-expansion__body`; the chevron turns on `[open]`. Open it by clicking the `summary`; controls inside a summary stop their clicks and keys so they do not toggle it |
| Stream disclosure | partial | `streamDisclosure({ feed, open, onToggle, cls? })` — the "Show / Hide AI activity" strip at the foot of an AI dialog: the `[data-action=toggle-stream]` button (`aria-expanded`) over an always-mounted `<r2m-stream-llm>` in `.r2m-stream-disclosure__body` (`--open` gives it height), so no request made while the dialog is open is missed (Edit with AI, Generate voice prompt, Discover) |
| Filled icon | CSS | `icon(name, 'r2m-icon--filled')` turns the font's `FILL` axis on for one glyph (the default voice's star) |
| Field | partial | `field({ id, label, hint?, error?, inline?, cls? }, (attrs) => control)` — the stacked label (`<label for>`) over a native control, then the `.r2m-field__error` (`role=alert`, replaces the hint and reddens the control) or the `.r2m-field__hint`. The control callback binds what it is handed: `id=${attrs.id} aria-describedby=${attrs.describedBy} aria-invalid=${attrs.invalid}`, so the control is described only by text that is on screen; `controlValue(event)` beside it reads the text of the input, select or textarea an event came from |
| Config list | element | `<r2m-config-list>` with `items` (`ConfigListItem[]`: id, name, subtitle?, isActive?, badge?), `selectedId`, `busy`, `activeLabel` ("Active" / "Default"); the search box, New, one `.r2m-config-list__row[role=option]` per item (`__name`, `__subtitle`, the active chip) and a per-row `role=menu` popover behind the `__more` button (`aria-label="Actions for …"`) with the Make active / Duplicate / Delete `menuitem`s; emits `pick`, `create`, `make-active`, `duplicate`, `delete` with the id (the settings master list, design §6.4) |
| Config editor frame | partial | `configEditorFrame({ title, subtitle?, dirty, saving, canSave?, onSave, onCancel }, body)` — `section.r2m-config-editor-frame` with `__title`, the `__dirty` "Unsaved changes" status, the `__body` and the `__foot` Cancel / Save (spinner + "Saving…" while saving); the settings detail side |
| Master–detail | CSS | `.r2m-master-detail`: a 320 px list beside the editor, stacked under 900 px |
