# Primitive catalogue

The shared building blocks in `ui/` (and the `core/` and `help/` pieces pages build with). Feature elements are not listed: read their own file under `pages/<area>/`.

The rule for a new primitive: CSS on a native control by default; a partial (function returning a template) only when it wires ARIA or ids; an element only when it owns state or lifecycle. A PR that adds a primitive adds its row. The look is M3-flavoured: pill buttons, outlined fields with the label stacked above (not floating), density −1, no ripple.

| Primitive | Form | Usage |
|---|---|---|
| Icon | partial | `icon(name, cls?)` — `name` is an `IconName`; the committed font is a subset of exactly those names |
| Status chip | partial | `statusChip({ status, label, icon?, tooltip?, compact? })` — `status` is `ok`/`warn`/`error`/`info`/`busy`/`neutral`; colour + icon + text, never colour alone. The chip is not a live region (chips render in lists); a state change worth hearing goes through the announcer (`announce()`, see Announcer), as a toast already does. A `tooltip` that differs from `label` is also the chip's accessible description (`withTip`, see Tooltip) |
| Empty state | partial | `emptyState({ icon, headline, hint?, compact? }, actions?)` — at most two `EmptyStateAction`s, `{ label, icon?, run }` (an in-place command, a button) or `{ label, icon?, href }` (lives elsewhere, a link button); the first is filled, each is `.r2m-empty-state__action`. The label is the real control's exact button label |
| Gated | partial | `gated(block, (gate) => control, { tabbable? })` (`ui/gate.ts`, exported by `ui/partials.ts`) — renders a control behind its Edit gate (`Block | null`). Put `${gate.attrs(ownTip?)}` on the control element itself (on each radio of a group): it is the control's only source of `disabled` and `data-tooltip`. While the gate has a reason the control stays focusable with `aria-disabled="true"`, `aria-describedby` pointing at a visually hidden copy of the reason (`aria-hidden`, so a tree row or `<summary>` is not named by it) and the reason as its tooltip in place of its own; a text field is also `readonly`. One capturing listener on the document refuses its click, Enter and Space, a select's, slider's or radio's value keys, and any `input` / `change`, so a caller adds no guard. Blocked without a reason it is plain `disabled`; open, it carries only its own tooltip. The element is the same through every change, and keeps focus. `tabbable: false` keeps a blocked control out of the tab order (a tree node's Node menu trigger). `gate.hover()` on a label or other surround shows the reason there too; wrap the `<label>`, not the field inside it, so the description stays out of the field's name. A custom element that renders its own button takes the gate as `.gate=${gate}` and `gate.blocked` for what else turns off (`r2m-speaker-chip`, `r2m-audio-player`). `control` runs at once, so the signals it reads are tracked. A control style with a `:disabled` look gives `[aria-disabled='true']` the same one, and its `:hover` skips both. Fold local conditions into `block` with `withLocal` ([user-messages.md](user-messages.md#blocked-reasons)) |
| Callout | partial | `callout({ kind, text, action? })` — `kind` is `info`/`warn`; a `.r2m-callout` banner with no dismiss and at most one `MessageAction` (`.r2m-callout__action`) |
| Advice line | partial | `adviceLine(text \| null)` — a muted `<p class="r2m-advice">`, or nothing |
| Help text | partial | `helpText(step, { title? })` (`help/help.ts`, not `ui/`: it is bound to the generated help module) — a `<section class="r2m-help" data-step=…>` with the step's title as its labelled `<h2>` (`title: false` leaves the heading to the host) and the build-rendered body (`## How` → `<h3>`) through `unsafeHTML`; shown through the Overview's `helpPanel(step, onClose, placement)` (`pages/project/help-panel.ts`: icon + name, close ×, the body, an "Open the guide" link to `docs/guide/<step>.md` on GitHub) only |
| Count badge | partial | `countBadge(kind, count, tooltip, showZero?)` — `kind` is `attribution`/`audio`/`review`; renders nothing at zero unless asked. The `tooltip` says what the count is of and is also the badge's accessible description (`withTip`, see Tooltip) |
| Button | CSS | `<button class="r2m-button">` is the text variant; add `r2m-button--filled`, `--stroked` or `--danger` |
| Icon button | CSS | `<button class="r2m-icon-button">` or an `<a>` with the same class: a 40 px round hit area around one `icon()`, colour inherited from its bar; give it `aria-label` and `data-tooltip` |
| Field | CSS | `.r2m-field` wrapping a `.r2m-field__label` and a native control, then an optional `.r2m-field__hint` or `.r2m-field__error` (which also reddens the control's border); `.r2m-field--inline` for a label beside the control (the `field()` partial in `ui/field.ts` wires `aria-describedby`; see the Field partial row) |
| Checkbox | CSS | native `<input type=checkbox class="r2m-checkbox">` |
| Switch | CSS | `<label class="r2m-switch"><input type=checkbox role=switch> Text</label>`: a track with a knob drawn on the checkbox, `accent` when checked |
| Radio group | CSS | `<fieldset class="r2m-radio-group" role=radiogroup aria-label=…>` of `<label class="r2m-radio"><input type=radio …> Text</label>`; the segmented control is the button-toggle look, not this |
| Page header | CSS | `.r2m-page-header` with `__title` and `__subtitle`, and `__actions` for controls at its end (the themes page's switch + New, the services page's Refresh all) |
| Dialog | core + CSS | `openDialog(el)` wraps `el` in a `<dialog class="r2m-dialog">` and resolves with the `r2m-close` detail; the content uses `.r2m-dialog__title`, `__content` and `__actions`. Every dialog is named: `aria-labelledby` its first `.r2m-dialog__title` (given an id when it has none), or `{ ariaLabel }` for one with no visible title, which wins over the title. Content holding unsaved work, or that must not close for a while (an upload in flight), implements `canClose(): boolean | Promise<boolean>` (`ClosableContent`): every `cancel` (Escape, a backdrop click under `closedby="any"`, `requestClose()`) asks it and the dialog closes only on `true`; a second `cancel` while it asks is swallowed. Its Cancel button calls `requestDialogClose(this)` (`requestClose()`, Chromium 134, Firefox 139, with a fallback), not `r2m-close`, so it goes through the same guard. `{ closedBy: 'none' }` skips the guard |
| Announcer | function | `announce(text, priority?)` (`ui/announcer.ts`) says something to a screen reader without moving focus. Announce through it, never build a live region; `assertive` is only for data loss, a lost connection or failures, and the default is `polite`. It calls `ariaNotify` on the topmost modal (`topmostModal()` in `core/dialog.ts`), since everything outside a modal is inert, and on the document when none is open; a browser without `ariaNotify` (before Chromium 141, Firefox 150) hears nothing |
| Visually hidden | CSS | `.visually-hidden`: text out of view but in the accessibility tree; it shows while it, or something inside it, has focus or is being pressed (a skip link styles that visible state itself) |
| Menu | CSS | a `[popover].r2m-menu` anchored to its invoker by CSS anchor positioning; the invoker is a `<button popovertarget=…>`, so the browser handles light dismiss, Escape and the top layer (the speaker chip's menu is one). A plain entry is a `<button class="r2m-menu__item">` with an optional leading `icon()` (`--destructive` for a delete); `<hr class="r2m-menu__divider">` separates groups; a choice among several carries `role="menuitemradio"` + `aria-checked` (the shell's theme menu). `menuItem({ label, run, icon?, hint?, action?, destructive?, disabled? })` (`ui/menu.ts`) renders an entry that closes its popover before it runs, `hint` as a muted second line (`.r2m-menu__hint`); `menuHeading(text)` is a non-interactive `.r2m-menu__heading` over a group. Every `role="menu"` popover binds `menuKeys` (`@keydown=${menuKeys.keydown} @toggle=${menuKeys.toggle}`): Up/Down move between enabled items (wrapping), Home/End go to the first and last, one item is in the tab order so Tab leaves, and an open by Enter or Space on the trigger focuses the first enabled item (a pointer open leaves focus); the node menu has its own keys over `rovingKeydown` |
| Select | CSS | a native `<select>`; under `@supports (appearance: base-select)` Chromium styles the picker, Firefox keeps its own |
| Confirm dialog | element + service | `use(ConfirmService).confirm({ … })` → `boolean`; renders `<r2m-confirm-dialog>` with `.r2m-confirm-dialog__confirm`. Focus opens on the confirm button, except a `destructive` confirm opens on `.r2m-confirm-dialog__cancel`, so an Enter or Space straight after it opens keeps the thing (modern-web-guidance `dialog`) |
| Permanent-change confirm | function | `confirmPermanent(change: PermanentChange \| null)` → `boolean` (true at once for null); `permanentConfirmOptions(change)` is the pure mapping onto `ConfirmOptions` (conventions 12) |
| Text prompt dialog | element + service | `use(PromptService).text({ … })` → `string` or `null`; renders `<r2m-text-prompt-dialog>` with `__input` / `__confirm` |
| Toast | service | `use(ToastService).success/info/warn/error(message)` and `.problem(problemDetails)`; `.info(message, actions)` adds `.r2m-toast__action` buttons (`{ label, run }`, each dismisses the toast) and keeps it up 12 s; stack is `.r2m-toasts` (a `region` named Notifications), each toast `.r2m-toast--<severity>` with its message in `.r2m-toast__text`. Every message is said through `announce()` (`error` assertively, "Actions available" added when it has actions), so a toast carries no live-region role. Each has a Dismiss button (`.r2m-toast__dismiss`). The countdown pauses while the toast has focus or the pointer and runs out what was left once both have gone. Dismissing a toast that holds focus moves it to the next toast's first control, else back to what had focus before it entered the stack. A toast raised while a modal is open mounts the stack inside the topmost one (`topmostModal()`), where it can be clicked and heard, and the stack moves on as that dialog closes |
| Tooltip | CSS + one installer, `withTip` | put `data-tooltip="…"` on the element; `installTooltips()` runs once from `main.ts` and owns the single `.r2m-tooltip` popover. The popover is the visual cue only and no trigger points at it. A tip equal to the trigger's accessible name (an icon button's `aria-label`) needs nothing more; one that says more is also rendered as the trigger's accessible description through `withTip(text, name, ({ tooltip, describedBy, description }) => template)` (`ui/tooltip.ts`): bind `data-tooltip` and `aria-describedby`, and place `description` (a `.visually-hidden` span with an id, nothing when `text` equals `name`) inside a positioned box, so its absolute position can't stretch a scrolling container. Status chip, Count badge and Job pill do this; Gated's blocked reason and the page-level tips that say more than their name are not wired yet. The tip can be hovered (WCAG 1.4.13): leaving the trigger or the tip hides it after 200 ms, entering either cancels that, and entering the tip also drops a pending switch to another trigger; focus out (unless the pointer is on the tip) and Escape hide it at once. It sits at `position-area: block-end`, off the axis of a horizontal bar. Over a vertical list it covers the top of the next row while open; that row still takes the hover below the tip, which then closes. Add `data-tooltip-overflow` to show it only when the element's text is cut off at show time (`scrollWidth > clientWidth`, measured per hover or focus), and `data-tooltip-delegate="<selector>"` on a focusable element with no tip of its own to show its descendant's tip on focus (the structure tree's rows and `.tree__title`) |
| Measured list | element | `<r2m-measured-list>` — set `key`, `row`, then `items`; emits `r2m-top-row`; `scrollToIndex` / `scrollToOffset` / `offsetOf` / `scrollOffset`; rows are `flow-root`, keyed on ids, re-measured one by one through a `ResizeObserver` |
| Segmented control | CSS | `<fieldset class="r2m-segmented" role="radiogroup" aria-label=…>` of `<label><input type=radio …> Text</label>`; locate the group by role and click a label by text |
| Control bar | markup | a `<div role="group" aria-label=…>` of mixed controls (the reader's `.book__toolbar`, named "Reader"): each control keeps its own Tab stop and no arrow keys move between them. `role="toolbar"` is only for a bar with one Tab stop and a roving tabindex (modern-web-guidance `toolbar`); a bare `div` may not carry `aria-label`, so it takes `group` |
| Speaker chip | element | `<r2m-speaker-chip>` with `name`, `characterId`, `state` (`named`/`unknown`/`mixed`/`narration`/`narrator-linked`), `roster`, `compact`; with a `roster` it is a `button` that hosts the menu (search focused on open unless the pointer is coarse) and re-emits its events; `gate` (from `gated`, whose caller hands no roster while blocked) offers no menu while blocked, and keeps it a button that says why while the gate has a reason (gate only a chip that has a roster to offer) |
| Speaker menu | element | `<r2m-speaker-menu>` with `roster`, `selectedId`, `allowClear`, `allowCreate`; emits bubbling `pick`, `clear`, `create` |
| Outlet | element | `<r2m-outlet>` renders the matched route (core, not `ui/`) |
| Navigation drawer | shell | the `app-root` rail (`shell/shell.ts`, not `ui/`): a docked sidebar at 900 px and wider, where the toggle's `aria-expanded` is the rail's expanded state. Narrower, it is an ordinary element the shell makes modal while open: the toggle's `aria-expanded` is `true`, focus moves to the first nav link, everything else in the shell is `inert` (`.shell__main`, the banners, the sheets, the activity bar and the app-bar controls in `.shell__appbar-controls`, so only the toggle stays), and Escape, the scrim, the toggle or a nav link close it through `closeModalRail`, which gives focus back to the toggle. Widening closes it |
| Spinner | partial | `spinner(size?, cls?)` — an indeterminate `role=progressbar` ring in `currentColor` |
| Progress bar | CSS | a native `<progress max="1" value=…>`; omit `value` for the indeterminate sweep |
| Placeholder title | CSS | `.r2m-placeholder-title` (muted italic) on the element showing an untitled node's **Placeholder title**; `placeholderTitleClass(nodeTitle)` from `pages/book/book-tree` picks it from `untitled`, never from the label text. The tree's `.tree__title` and the Book page's `.book__volume` / `.book__part` / `.book__chapter` headings carry it |
| Tabs | partial | `tabs({ id, tabs, selected, onSelect, label? })` renders a `role=tablist` of `role=tab` buttons (`data-tab`, `aria-selected`, `aria-controls`) with automatic activation over the roving helper; `tabPanel(id, tab, content)` is the matching `role=tabpanel`. Locate a tab by role and name |
| Bottom sheet | core + CSS | `openDialog(el, { variant: 'sheet', closedBy: 'none' })`: the dialog gets `r2m-dialog--sheet` and docks to the bottom edge |
| Full-screen dialog | core + CSS | `openDialog(el, { variant: 'fullscreen' })`: the dialog gets `r2m-dialog--fullscreen` and fills the viewport |
| Job pill | partial | `jobPill({ job, onOpen, onCancel, tooltip? })` — `.r2m-job-pill` with `__main` (opens the drawer) and `__cancel`; `job` is a `JobView` (`ui/job.ts`: `formatDuration`, `jobSummary`, `JOB_ICONS`). The `tooltip` shows over the whole pill and, when it differs from `job.label`, is the `__main` button's accessible description (`withTip`, see Tooltip) |
| Job card | partial | `jobCard({ job, history?, onCancel, onDismiss })` — `.r2m-job-card` with the numbers `<dl>`, a `<progress>`, an optional sparkline and the Cancel / Dismiss footer |
| Throughput | partial | `throughput(snapshot)` — headline, sparkline and the per-config `.r2m-throughput__table` once the run ended; `sparkline({ values, width?, height?, stroke?, label? })` on its own |
| Docker controls | partial | `dockerControls({ status, busy?, statusOnly?, serviceName?, onStart?, onRestart?, onShutdown?, onRefresh })` — the status chip plus Start / Restart / Shutdown / Refresh icon buttons (by `aria-label`); `SERVICE_STATUS_VIEW` maps `AiServiceStatus` to chip kind + label |
| LLM stream | element | `<r2m-stream-llm>` with `events` (`LlmStreamEvent[]`) and `maxTurns`; folds turns with `ui/llm-turns.ts`, autoscroll pauses on scroll-up (`paused`, "Jump to latest") |
| Audio stream | element | `<r2m-stream-audio>` with `events` (`AudioGenEvent[]`) and `maxCards`; folds cards with `ui/audio-cards.ts`, same autoscroll |
| Preflight sheet | element | `<r2m-preflight-sheet>` with `data: { kind, label, plan }`; owns the plan → running → done/failed phases and the `/run` call, emits `r2m-close` with `true`/`false`. Opened only by `Preflight.ensureReady` |
| Audio player | element | `<r2m-audio-player>` with `src`, `cacheKey` (the `?v=` buster), `label`, `compact`, `gate` (from `gated`: its play button takes the gate, so a player blocked with a reason says why), and `srcB` / `labelA` / `labelB` for the A/B variant; `.r2m-audio-player__toggle` (Play/Pause by `aria-label`), `__scrub`, `__time`, `__error`; emits `playback-ended` and `ab`. `formatClock` is exported. `workspaceUrl(folder, file, version?)` in `api/` builds the `/workspace/…` source |
| File drop | element | `<r2m-file-drop>` with `accept` (native syntax: extensions and/or MIME types), `maxBytes`, `multiple`, `label`, `hint`, `block` (its Edit gate, `Block | null`: while blocked the "Choose file" button is off through `gated`, a drag is refused and a drop ignored, and the zone takes `r2m-file-drop--read-only`); a dashed drop zone with a "Choose file" button; emits `files` (`File[]`) and `rejected` (`RejectedFile[]`, reason `type` or `size`). The hidden picker keeps `.r2m-file-drop__input` so a browser test can `SetInputFiles` on it |
| Inline edit | element | `<r2m-inline-edit>` with `value`, `placeholder`, `required`, `maxLength`, `block` (its Edit gate: while blocked it never opens and its button is off through `gated`); a `.r2m-inline-edit__display` button that becomes the `.r2m-inline-edit__input` on click (focused and selected). Enter and blur save, Escape cancels; mid IME composition Enter and Escape do nothing. After Enter or Escape the display button takes focus; a blur-save leaves focus where it went. Emits `save` only for a changed, valid value, else `cancelled` |
| Splitter | element | `<r2m-splitter>` with `value` (px, the pane before it), `min`, `max`, `defaultValue`, `orientation` (ARIA's: `vertical`, the default, sits between columns and takes `col-resize`; `horizontal` takes `row-resize`) and `label` (its accessible name); the host is a focusable `role=separator` with `aria-valuenow`/`min`/`max` (the value clamped). Nothing drawn at rest: a thin accent handle on hover, focus and drag |

| Project card | partial | `projectCard(project, { onOpen, onDelete, deleting?, seriesLine?, badge?, menuEntries?, extra? })` — `.r2m-project-card[data-folder]` with the `__cover` button (workspace image or `placeholderGradient` + `projectInitials`), the `__title` button, the `__more` icon button (`aria-label="Actions for …"`) opening a `role=menu` popover with the `__open` / `__delete` `menuitem`s with `menuEntries` between them, the `__author` line, the `__series` line, the cover's `__badge`, `extra` under the author, and the `__progress` bar or `__unread` |
