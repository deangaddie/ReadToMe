# What the status path, voice rules and audio review give the Voices and Audio rows

Research for the Voices and audio guidance map (`.scratch/guidance-voices-audio`), resolved 2026-10-17 against the repo at `00e6b25`. Every claim carries a `file:line` pointer relative to the repo root. Vocabulary follows `context/voice-rules.md`, `context/audio-pipeline.md`, `context/semantic-verification.md`, `context/book-structure.md` and `context/web.md`.

Three things the map's "Facts today" got wrong, up front:

- `ReadyVoices` is **not** a voice count. It is the number of distinct speakers that have at least one Ready Voice, so the stepper's subtraction is already per character (§1).
- **Neither Edit text nor Edit with AI** carries any audio wording today; Edit text's silence is deliberate (§3).
- The Audio mode row offers **Dismiss** on a flagged item but **Retry only on a queue failure**, not on a review flag (§4).

## 1. Voices count

**The DTO and the endpoint.** `ProjectStatusDto(HasContent, Characters, CharactersWithLines, ReadyVoices, Items, Attribution, Audio, Review, VolumeIds, Nodes, Revision)` — `src/Read2Me.App/Api/ProjectStatusEndpoints.cs:26-37`, served at `GET /api/projects/{folder}/status` (`:43`). The handler makes several sequential reads, not one query: a NodeStatus reseed (`:60`, `:108-114`), volumes (`:61`), per-node item counts (`:62`), `characters.GetCastCountsAsync` (`:63`) and `HasBookContentAsync` (`:74`). The cast fields are copied straight from `CastCounts` (`:75-77`).

**What the two numbers count.** `CastCounts(int Characters, int CharactersWithLines, int ReadyVoices)` — `src/Read2Me.Services/IProjectReader.cs:273`, doc at `:268-271`. Implementation `src/Read2Me.Services/ProjectReader.Characters.cs:325-350`:

- `Characters` = `db.Characters.CountAsync(c => !c.IsNarrator)` (`:329`): the seed Narrator row is excluded.
- `CharactersWithLines` = distinct non-null `CharacterId` over items where `ItemType == Speech` (`:330-335`; the predicate is `src/Read2Me.Data/ParagraphItemKinds.cs:37-38`), then the narrator sentinel is remapped to the linked character (`:338-341`). Pauses never count; an item whose speaker is unset never counts.
- `ReadyVoices` = distinct `Voice.CharacterId` where `AudioFileName` is non-empty (`:343-347`), **intersected with the speaker set** (`:349`, `withAudio.Count(speakers.Contains)`). The readiness rule is the same one as `src/Read2Me.Services/Voice/VoiceReadiness.cs:13` (`!string.IsNullOrEmpty(voice.AudioFileName)`): a designed voice with a prompt and no audio is not ready.

So one character with two Ready Voices counts once, a silent character's Ready Voice counts zero, and `charactersWithLines - readyVoices` is exactly "speakers without a Ready Voice". The table test pins it: Alice with two ready voices, Bob with a voice without audio, a silent character with a ready voice gives `CastCounts(3, 2, 1)` — `src/Read2Me.Tests/Services/CastCountsTests.cs:70-90`.

**Narrator.** Narration items carry `CharacterId = ProjectDbContext.NarratorId` forever (`src/Read2Me.Data/ProjectDbContext.cs:8`, seed row `:43`; `src/Read2Me.Data/NarrationRule.cs:27-28`). `NarratorIdentity.LoadAsync` (`src/Read2Me.Data/NarratorIdentity.cs:27-54`) resolves that id to the linked character when `Project.NarratorCharacterId` is set (`src/Read2Me.Data/Entities/Project.cs:21`), else to `Unlinked` (`:17-18`). Consequences:

- **Unlinked book:** the seed Narrator counts as a speaker with lines but not as a character, so M can exceed the cast count by one (`CastCountsTests.cs:58-67`: narration only gives `Characters 0, CharactersWithLines 1, ReadyVoices 0`). Its own Voice rows count toward `ReadyVoices` once it has one with audio.
- **Linked book:** narration is credited to the linked character, who counts once even if they also have dialog (`CastCountsTests.cs:93-107`: `(1, 1, 1)`).

**The stepper.** `src/Read2Me.Web/src/app/pages/project/pipeline-steps.ts:117` `const voicesMissing = Math.max(0, s.charactersWithLines - s.readyVoices);`; state at `:118-124` (`notStarted` when no speakers, `remaining` while `voicesMissing > 0`, `running` during a voice batch); chip label `${voicesMissing} remaining` (`:227`); detail text is `"${readyVoices} of ${charactersWithLines} speakers have a voice with audio"` (`:231`) — the phrase "speakers voiced" does not exist in the web source. The `Math.max` is defensive only; the intersection means it cannot go negative except in a race. No other web code reads these two fields (`src/Read2Me.Web/src/app/api/dtos.ts:155-156` types them).

**Cost of a per-character count.** Nothing to build: the rule is already per character. For reference, the queries touch `ParagraphItems` (indexed on `CharacterId` and `ParagraphId`, not on `ItemType` — `src/Read2Me.Data/Migrations/ProjectDbContextModelSnapshot.cs:204-206`), `Voices` (indexed on `CharacterId`, `:328`; no index on `AudioFileName`) and the `Projects` row. The speaker `DISTINCT` is a scan of `ParagraphItems` filtered by `ItemType`; the `Voices` scan is tiny. `/status` is not polled: `src/Read2Me.Web/src/app/pages/project/project-store.ts:108` on open and `refreshStatus` (`:139`) on any receipt whose facets meet `STATUS_FACETS` (`'Structure','Attribution','Audio','Reviews','Characters','Narrator','Voices'`, `:22-30`), a revision gap (`:172-180`) or a resync (`:193`), debounced to one call per 250 ms (`src/Read2Me.Web/src/app/shared/debounced.ts:2`). During an audio run each recorded take is an `Audio` facet, so `/status` (with the cast queries and a NodeStatus reseed) runs about four times a second at most.

## 2. Dangling anchors

**Model.** `VoiceRule` has `FromLevel`/`FromNodeId`/`ToLevel`/`ToNodeId` (`src/Read2Me.Data/Entities/VoiceRule.cs:13-16`). The ids have no foreign key by design: `src/Read2Me.Data/ProjectDbContext.cs:105-108` — "FromNodeId/ToNodeId are polymorphic across 5 tables and may dangle by design (ADR-0002) … dangling anchors are flagged in UI, never silently deleted." An anchor can name a Volume, Part, Chapter, Paragraph or ParagraphItem.

**Where the flag is computed: twice, on read, never stored.**

1. Resolution path. `src/Read2Me.Services/Voice/AnchorSpanResolver.cs:19` and `:29` call `tables.TryResolve(...)`, and `:32-33` `var isDangling = (rule.FromNodeId.HasValue && fromDangling) || (rule.ToNodeId.HasValue && toDangling);`. `NodeOrderTables.TryResolve` returns false when the id is missing from that level's order dictionary (`src/Read2Me.Services/Voice/NodeOrderTables.cs:20-21`, repeated per level at `:28`, `:36`, `:44`, `:52`). Used by `VoiceResolver` (`src/Read2Me.Services/Voice/VoiceResolver.cs:82`, `:95`) and the chapter preview (`src/Read2Me.Services/Voice/VoiceRulePreview.cs:42-43`). Effect: `src/Read2Me.Services/Voice/VoiceRuleEvaluator.cs:24` `if (rule.IsDangling) continue;` — the rule is skipped silently and the Default Voice Rule takes over.
2. Voice-rules GET. `GetCharacterVoiceRulesAsync` (`src/Read2Me.Services/ProjectReader.Characters.cs:56`) resolves display names per level and sets `dangling = true` when the node is not found (`ResolveDisplayName`, `:138-168`, flag at `:166`; called per rule at `:174-175`). Surfaced as `VoiceRuleDto(... FromTitle, FromDangling, ... ToTitle, ToDangling, Order)` (`src/Read2Me.App/Api/CharacterEndpoints.cs:40-44`, mapping `:120`) on `GET /api/projects/{folder}/characters/{id}/voice-rules` (`:57`), one character at a time.

**Per-project count: none exists.** `CharacterSummaryDto` carries only `LineCount, VoiceCount, ReadyVoiceCount, IsNarrator, NarratesBook` (`CharacterEndpoints.cs:16-18`; query `ProjectReader.Characters.cs:217-235`). No status, overview or summary DTO mentions dangling. One query away: because the anchor is polymorphic there is no single `Node` table to LEFT JOIN, but one round trip works either as five level-conditioned LEFT JOINs or a `NOT EXISTS` chosen by a CASE on the level, counting distinct `VoiceRules.Id` (optionally grouped by `CharacterId`). It belongs next to `GetCharacterSummariesAsync` on `ICharacterReader` (`src/Read2Me.Services/IProjectReader.cs:229`), and its "missing" rule must match `ResolveDisplayName` and `NodeOrderTables.TryResolve`. The receipt facet to refetch on is `VoiceRules` plus `Structure` (a reread or a node delete is what makes an anchor dangle).

**How the UI flags it.** DTO fields `fromDangling`/`toDangling` are hand-typed in `src/Read2Me.Web/src/app/api/dtos.ts:472` and `:476` (the generated `schema.d.ts` does not type this response, `src/Read2Me.Web/src/app/api/schema.d.ts:706-724`). `isDangling(rule)` — `src/Read2Me.Web/src/app/pages/cast/voice-rules/voice-rule-logic.ts:42-43`; the anchor label becomes `'(missing node)'` (`:20`). The row gets class `voice-rules__row--dangling` and a warning icon with `data-tooltip="One or more anchor nodes no longer exist; this rule is skipped"`, `aria-label="Missing node"` (`src/Read2Me.Web/src/app/pages/cast/voice-rules/voice-rules-section.ts:115`, `:121-127`; colour `src/Read2Me.Web/src/app/pages/cast/cast.css:589-592`). Nothing outside the section shows it: the roster row shows alias count and readiness chip only (`src/Read2Me.Web/src/app/pages/cast/cast-page.ts:268-301`), and no other page renders rules.

**When the section renders.** Mounted unconditionally in the character detail (`src/Read2Me.Web/src/app/pages/cast/character-detail.ts:116-118`) but returns `nothing` until a rule exists (`voice-rules-section.ts:53` `if (!character || rules.length === 0) return nothing;`; doc `:18-19` "the first voice brings the default one"). Add rule is hidden for the seed Narrator (`:63`) and disabled while the character has no voices (`:69`). A character with no voice therefore never sees that voice rules exist.

## 3. Audio invalidation

**Only two things clear an item's audio.** No path deletes a WAV from disk; each sets `ParagraphItem.AudioFileName` to null. Items do not record which voice produced their audio (`src/Read2Me.Data/Entities/ParagraphItem.cs:7-14`), so no voice-side change can find stale item audio.

1. `BookEditEffects.DiscardAudioAsync` — `src/Read2Me.Services/Mutations/Implementations/BookEditMutationImplementations.cs:128-145`: reports `Audio` only when audio existed (`:132`), nulls the file name (`:133`), and **deletes** any `AudioReview` rows, adding `Reviews` (`:140-141`; doc `:98` "deleted, not dismissed"). Reached through `RewriteAsync` (`:110-117`, no-op when the text is unchanged) from `UpdateParagraphItemText` (`:193`), `ApplyBookEdits` (`:287`) and directly from `SetItemDeliveryCue` (`:243`).
2. Inline clears in the speaker family — `src/Read2Me.Services/Mutations/Implementations/SpeakerAttributionMutationImplementations.cs:65` (`item.AudioFileName = null;   // a hand-flip discards the item's audio (ADR-0006)`), `:111`, `:162`, `:202`. **None touches `AudioReviews`**, so a flagged item that is reassigned keeps a NeedsReview row with no audio behind it (it still counts in `Review` and still renders its chip; the row is corrected only when the item is regenerated, §4). ## 4. Review state

**What `Review` counts.** Paragraphs with at least one item whose `AudioReview` row is in `NeedsReview`; Dismissed is excluded — `ProjectStatusEndpoints.cs:84` `Review: seed.Count(r => r.Review > 0)` over `src/Read2Me.Services/ProjectReader.Audio.cs:148-162` (join `AudioReviews` where `State == NeedsReview` to items, distinct paragraph ids). Only paragraphs with a Speech item appear in the seed (`:128-129`). **No web UI reads `ProjectStatusDto.review`** (`dtos.ts:160` types it); the only consumer of the count is the per-node tree badge: `src/Read2Me.Web/src/app/pages/book/structure-tree.ts:373` `countBadge('review', s.review, 'Paragraphs with audio to review')`, fed by `src/Read2Me.Services/NodeStatus/NodeStatusService.cs:141-166` (`:156`), and `IsDone => AttributionRemaining == 0 && AudioRemaining == 0 && Review == 0` (`:26`). Glossary: `context/book-structure.md:45-46`.

**Entity and states.** `src/Read2Me.Data/Entities/AudioReview.cs:5-24`: `ParagraphItemId` (unique, `ProjectDbContext.cs:137`), `State`, `NormalizeOk/NormalizeReason`, `VerifyOk/Wer/VerifyReason`, `Transcript`, `OriginalTextSnapshot`, timestamps. `enum AudioReviewState { NeedsReview, Dismissed }` — `src/Read2Me.Data/Enums/AudioReviewState.cs:3-7` (mirror `src/Read2Me.Core/Models/BookCommands.cs:188`). `AudioReviewVerdict` has no `Rescued` field.

**State machine** (`src/Read2Me.Services/Mutations/Implementations/AudioRecordingMutationImplementations.cs`):

- Every take is recorded by `IAudioResultRecorder` as one `RecordParagraphItemAudioMutation(folder, itemId, path, verdict)` (`src/Read2Me.Services/Audio/IAudioResultRecorder.cs:92-97`), which sets `AudioFileName` and applies the verdict (`:115-125`), facets `Audio | Reviews` when the review moved.
- `ApplyVerdictAsync` (`:48-73`): **normalize OK and verify OK → the row is deleted** (`:53-57`); otherwise a row is added in `NeedsReview` (`:61`), or an existing one is re-stamped to `NeedsReview` whenever anything differs, **state included** (`:69-71`, `Differs` `:76`, `Stamp` `:87`). Doc `:38-40`: "A fresh failure always returns the row to needs-review, which is what makes a dismissal cover the take it was given and not the next one."
- Dismiss (`:170-183`): `NeedsReview → Dismissed`; no-op when absent or already dismissed (`:176-177`). Command `DismissAudioReviewCommand(FolderId, ParagraphItemId)` — one item (`src/Read2Me.Core/Models/BookCommands.cs:201`), posted through `POST /api/projects/{folder}/commands` (`src/Read2Me.App/Api/CommandEndpoints.cs:16`; web `pages/book/audio-generator.ts:50-51`).
- Text and cue edits delete the row (§3). Speaker flips do not (§3).

So the lifecycle is: flagged by a failing take → cleared by a later take that passes (row deleted) or parked by Dismiss → re-flagged by any later failing take → deleted by a text or cue edit.

**Where flags come from** (`src/Read2Me.Services/Audio/AudioItemPipeline.cs`): normalize failure (`:147`, reason `"normalize failed"`, no retry, no verify); no transcription config (`:244`, reason `"no transcription config"`, `Wer` null — every take is flagged); WER over threshold (`:309-312`, reason `"WER x > t"`). Semantic Rescue (`:298-306`) returns a passing outcome, so a rescued take writes **no row**; "rescued" exists only in the activity stream (`src/Read2Me.Web/src/app/ui/audio-cards.ts:111`, `src/Read2Me.Web/src/app/ui/stream-audio.ts:27`).

**A dormant service.** `AudioReviewService` (`src/Read2Me.Services/Audio/AudioReviewService.cs:22-59`) is an in-memory mirror registered as a singleton (`src/Read2Me.App/Configuration/ServiceRegistrationExtensions.cs:125`) and read by the hub's `ProjectStatusSource` (`src/Read2Me.App/Live/ProjectStatusSource.cs:52`, `:57`), but **no production code calls `Set`, `Clear` or `Hydrate`** (callers are tests only). The hub's per-item `review` is therefore always null; the web falls back to the REST map (`reviewOf`, `pages/book/reader-rows.ts:202-205`), loaded by `GET /api/projects/{folder}/audio/reviews` (`src/Read2Me.App/Api/AudioEndpoints.cs:33`, DTO `:19-21`; web `book-store.ts:380-384`, reloaded on `reloadReviews`). Harmless today, but any "live review state" design must not assume the hub carries it.

**Bulk actions: none.** No bulk Dismiss, bulk retry of flagged items or "select flagged" on any surface; the only review action is the per-item Dismiss. Retry is `POST /api/projects/{folder}/audio/enqueue-items` with `ItemIds` (`AudioEndpoints.cs:29`; web `audio-generator.ts:45-46`), which already takes an array, so a bulk retry needs only a client that collects the flagged ids. The tree menu's "Select needs audio" (`pages/book/node-menu-entries.ts:223`) is the nearest selection shortcut and selects missing audio, not flagged items.

**What the Audio mode row shows** (`pages/book/item-row.ts`, `audioLine` `:167-227`): the review via `reviewOf` (`:168`); a Dismissed row renders as a faded icon with tooltip "Review dismissed" (`:182-189`); a NeedsReview row renders the chip plus a **Dismiss** button (`:190-199`); the **Retry** button appears only on a queue failure (`queue && outcome && voiced`, `:204-213`), not on a review flag; the compact player (`:218-223`). The chip (`reader-rows.ts:127-156`): `'Normalize failed'` with the reason as tooltip (`:134-140`); `'Verify failed'` with tooltip `WER nn%` joined to the reason (`:142-153`). **WER is tooltip-only, there is no rescued indicator, and the transcript / original-text snapshot are not shown.**

## 7. Deep links

**Params read.** Only `mode` and `chapter`. Modes `['read', 'speakers', 'audio']`, unknown falls back to `read` (`src/Read2Me.Web/src/app/pages/book/reader-rows.ts:26-31`), read in an effect at `src/Read2Me.Web/src/app/pages/book/book-page.ts:241-244`, written by `setMode` with `replace` (`:605-611`, `read` clears the key). `?chapter=` is a **chapter node id (Guid)**, read once in `start()` (`:876-878`): if given and not in the window → `openChapter`, else if the window is empty → `openFirstChapter`. A tree pick writes it (`:537-545`); scrolling does not update it (`onTopRow` `:614-618`). `openChapter` scrolls the list to the chapter header (`book-store.ts:259-268`, `:267`; `book-page.ts:262-266`, `scrollToChapter` `:881-893`, `reachScrollTarget` `:935-945`) and marks the chapter current in the tree (`:269-273`); nothing is selected and there is no paragraph or item target. **Stale id:** `openChapter` sets the window to that id and `readOrMarkStale` sets the stale banner on failure (`book-store.ts:446-451`); `chapters()` filters out ids without paragraphs (`:106-107`), so the page shows the skeleton plus "This view may be out of date" with a Refresh that fails the same way (`book-page.ts:327-334`, `:371-381`) — there is no fallback to the first chapter.

**Cheapest route to a flagged-only view.** Hook `buildRows(chapters, mode)` (`reader-rows.ts:252-282`), which already hides rows by mode (pause paragraphs only outside `read`, `:261-278`) and is wired as `this.rows = computed(() => buildRows(store.chapters(), store.mode()))` (`book-page.ts:191`) into `<r2m-measured-list .items=${rows}>` (`:382-389`). The alternative "land on the first flagged chapter" needs no new state: `?mode=audio&chapter=<id>` with the id chosen client-side from `nodes[*].review > 0` in book order.

## Observations the map can use

- **Voices row arithmetic is already right.** `readyVoices` is "speakers with ≥1 Ready Voice", so "N of M" and "K remaining" need no host change. What the host lacks is *which* speakers are unvoiced; `CharacterSummaryDto.ReadyVoiceCount` + `LineCount` on the cast list gives that per character already.
- **Narrator in the count:** an unlinked Narrator is a speaker with lines (M includes it, the cast count does not), so a fresh book with no narrator voice reads "0 of 1 speakers have a voice with audio" before any character exists. The Voices row copy should expect that.
- **Dangling anchors** are deterministic, computed on two read paths, and surfaced only as a warning icon inside a section that renders only once a rule exists. A project-wide count is one new reader query on `ICharacterReader` (five-table polymorphic anchor, no single join) refetched on `VoiceRules | Structure`.
- **"Audio clears" advice:** the only edits with audio wording today are Delivery cue, Release narration and Reread. Edit text (deliberately), Edit with AI, single/paragraph speaker assign and Bulk assign have none; the map's assumption that Edit text and Edit with AI already carry a line is wrong. Bulk assign's preview has no audio count, so a line there needs a host addition. Attribution answers, voice changes, voice-rule changes, character merge/delete and Merge item never clear audio — the latter leaves a WAV behind text that changed.
- **Review state has three edges** a review surface must respect: speaker flips keep a stale NeedsReview row on an item with no audio; `AudioReviewService` is never fed, so the hub does not carry review state (REST map only); Retry is wired to queue failures, not review flags, so "clear by retrying" means enqueueing the item (the enqueue API already takes an array for a bulk version).
- **Voice batch** has no per-voice failure record: the only trace is the completion toast's failed count. A Voices callout for "voices that failed to generate" would need the runner to store `FailReason` per voice first.
- **Settings at point of need:** a missing active config is invisible until the action fails (409 toast for TTS, a flagged chip on every item for transcription, failed rows for LLM); preflight never reports it. `GET /api/settings/{area}/active` 404s cleanly, so a row-level "no active X config" line is a cheap client check. ffmpeg missing degrades paragraph audio to "Normalize failed" on every item and blocks voice upload with a 422.
- **Deep links:** `?mode=audio&chapter=<chapterId>` is the whole vocabulary; a stale chapter id strands the page. A flagged-only view is a `buildRows` predicate over the existing review map; a flagged-first landing needs no new state.
