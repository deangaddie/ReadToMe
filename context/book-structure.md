# Book structure, view, selection & status

Use these terms exactly in code, tests, and discussion.

## Book structure

- **Volume / Part / Chapter / Paragraph / ParagraphItem** — book hierarchy, top to leaf. A Paragraph holds ordered ParagraphItems. An item is either **Speech** or one of the **Pause** kinds — `ParagraphItemType` answers exactly one question, is this a pause? What a speech item *is* comes from its speaker (`CharacterId`): the narrator sentinel = **narration**, null = **unattributed dialog**, any other Character = **attributed dialog** ([ADR 0006](../docs/adr/0006-narration-is-a-speaker-not-an-item-type.md)). Asked in one place only, **`NarrationRule`** (`Read2Me.Data`) — `IsNarration(item)` for a loaded item, `IsNarrationExpression` inside LINQ that must reach SQL.
  _Avoid_: "Narration item", "Character item" as *types* (the retired model), "retyping" an item — a narration↔dialog flip is a speaker assignment
- **Character paragraph** — a Paragraph with ≥1 **non-narrator** speech item: the unit of attribution selection, roll-up denominators and node status badges. One speaker assignment can switch it on or off, so a flip clears selection and reseeds counts — the same discipline a structural change follows.
- **Book Hierarchy** — in-memory `BookHierarchy` that plans structural mutations (split / merge / title insertion / item insertion) and returns a `HierarchyMutation` (ToAdd / ToDelete / ToUpdate). The deep planning module; `BookCommandHandler` dispatches commands to it. _Note_: pause-**paragraph** insertion is the one structural mutation that does **not** go through it — `InsertPauseParagraphHandler` computes its own orders.
- **Split** — a structural mutation that creates a **new parent** node: Split Volume (at a Part), Split Part (at a Chapter), Split Chapter (at a Paragraph), Split Paragraph (at a ParagraphItem). A split never divides a node's *text*.
- **Item insertion** — a new **Speech** ParagraphItem placed **Before** or **After** an anchor item, always **within the anchor's own Paragraph** (never crossing into a neighbouring one). Born **unattributed** — no speaker, no voice instructions, no audio — so it is not yet a **Generatable item**, and it raises the attribution-remaining badge. Never a Pause, and never anchored on a Pause item. The user's repair for a merged two-speaker item: edit the anchor's text down, insert, paste, assign. Distinct from **Split**, which makes a new parent rather than a new sibling.

## Characters

- **Alias** — alternate name for a Character (e.g. "Mr. Baggins" for "Bilbo Baggins"). Stored in `CharacterAliases`. Injected into the LLM attribution prompt alongside the canonical name and matched case-insensitively by the queue worker, so an alternate name resolves to the existing canonical Character instead of a duplicate.

## Book view

- **Book View Mode** (`BookViewMode { Combined, SplitAttribution, SplitAudio }`) — three mutually exclusive book-tab display states, selected via one dropdown. `Combined`: original paragraphs with attribution checkboxes. `SplitAttribution`: split ParagraphItems with Character-paragraph checkboxes for the attribution queue. `SplitAudio`: split ParagraphItems with per-item checkboxes for the audio queue plus play buttons. Replaces the old `bool SplitView`.

- **Book mutation** — one user or domain operation that changes the persisted Book, even when it touches several records or facets (a split, an accepted AI edit, a Character merge). Committed through `BookMutations.CommitAsync`, which owns per-project write serialization, the transaction, the single commit point and the revision. Returns a **Book mutation receipt**: project and mutation identity, revision, any created identity, the facets and identifiers *actually* affected, and structural split/merge relationships — facts, never instructions for how to reconcile. A valid operation that changes nothing is `NoChange` and consumes no revision ([ADR 0007](../docs/adr/0007-book-mutations-reconcile-book-view-projections.md)).
- **Book View projection** — the circuit-scoped `BookViewProjection` that turns receipts into one immutable **`BookViewSnapshot`**, published atomically. The persisted Book is authoritative; a projection is always rebuildable and never a second source of truth. Exact item-level effects allow targeted authoritative reads; structural, Book-wide and unknown effects rebuild the overview plus the branches expansion intent names. Both selections are **recomputed** against the new revision, not proven safe by the writer.
- **Stale Book View projection** — projection health after a targeted refresh *and* its rebuild fallback both failed. The last coherent snapshot stays visible, no partial candidate is ever published, further Book mutation gestures are refused, and `RetryRebuildAsync` is the recovery path. A mutation that committed before reconciliation failed reports **committed-but-stale** — distinct from `NoChange` and from an uncommitted failure.

## Selection

- **Folder Selection** (`FolderSelection`) — the set of Character paragraphs selected (per project folder) for the Character Queue. Source of truth: selected paragraph ids + each one's ancestry `(VolumeId, PartId, ChapterId)`.
- **Roll-up** — a node's tri-state (Unchecked / Indeterminate / Checked) is **derived** from how many of its selectable Character paragraphs are selected vs its total. Never stored; computed on read. Selecting a node selects all (or, **unprocessed-only**, the unprocessed subset of) its Character paragraphs; additive and idempotent.
- **Book Node Level** (`BookNodeLevel { Volume, Part, Chapter }`, in Core) — the selectable triad. One enum used by both the reader (scope Character-paragraph queries) and Folder Selection (derive roll-up). Replaces the old `SelectionNodeKind`.
- **Selectable node** — a Volume / Part / Chapter containing ≥1 Character paragraph. Only selectable nodes show a checkbox. Total counts (`NodeCharacterParagraphCounts`) seeded on load, held by `FolderSelection`. Selection cleared on any structural change (split / merge / item insertion / reread), so derived state never mixes counts across structures.
- **Audio Item Selection** (`AudioItemSelection`) — the set of ParagraphItems (speech only; Pause excluded) selected for the Audio Queue. Parallel to `FolderSelection` but at ParagraphItem granularity. Rolls up to Chapter/Part/Volume for tri-state. Cleared on view-mode switch or any structural change.
- **Generatable item** — a non-Pause ParagraphItem that can have audio generated: **missing audio** (no WAV) **and** **attribution-ready**, which with the speaker as the discriminator means simply **any speaker at all** — narration qualifies because it is stamped with the narrator, dialog once it has a Character, and only an unattributed item does not. The audio analog of an **unprocessed** attribution paragraph. The node-level "select needs audio" (`needsAudioOnly`) selects only Generatable items; an unattributed item's checkbox is disabled (not yet Generatable). A manual speaker flip **or a manual text edit** clears the item's WAV, returning it to Generatable; LLM stamping does not. A node's audio roll-up denominator counts *all* non-Pause items, so a needs-audio select lands on Indeterminate, never Checked.

## Node status

- **Node Status Badge** — a per-node (Volume / Part / Chapter) count of remaining work in the expansion-panel header. Three **stages**: **attribution remaining** (paragraphs with an unattributed item), **audio remaining** (paragraphs with a non-Pause item lacking a WAV — regardless of attribution), **review** (paragraphs with an `AudioReview` row in `NeedsReview`; `Dismissed` excluded). Counts **normalised to Paragraph granularity** — a paragraph qualifies for a stage if *any* item qualifies, contributing 1. All three at zero → single "done" indicator. Shown in every Book View Mode.
- **Node Status roll-up** — each badge is the **cumulative** count of qualifying paragraphs beneath it (Volume ≥ Part ≥ Chapter); the same paragraph echoes up every ancestor. Held by singleton `NodeStatusService`, storing per-paragraph stage **counters** (`unattributed`, `missingAudio`, `review`) + `(Chapter, Part, Volume)` ancestry. Seeded via `IProjectReader.GetNodeStatusSeedAsync`, updated **live**: `BookHierarchyPresenter` raises domain events — `OnCharacterAttributed` (with remaining unattributed count, assigned directly), `OnAudioAssigned` (decrements `missingAudio`), `OnReviewChanged` (sets review flag). The service owns the counter transition (assign vs decrement). **Cleared and reseeded** on any structural change — never patched incrementally, same discipline as `FolderSelection`.
