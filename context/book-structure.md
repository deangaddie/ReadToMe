# Book structure, view, selection & status

Use these terms exactly in code, tests, and discussion.

## Book structure

- **Volume / Part / Chapter / Paragraph / ParagraphItem** — book hierarchy, top to leaf. A Paragraph holds ordered ParagraphItems. An item is either **Speech** or one of the **Pause** kinds — `ParagraphItemType` answers exactly one question, is this a pause? What a speech item *is* comes from its speaker (`CharacterId`): the narrator sentinel = **narration**, null = **unattributed dialog**, any other Character = **attributed dialog** ([ADR 0006](../docs/adr/0006-narration-is-a-speaker-not-an-item-type.md)). Asked in one place only, **`NarrationRule`** (`Read2Me.Data`) — `IsNarration(item)` for a loaded item, `IsNarrationExpression` inside LINQ that must reach SQL.
  _Avoid_: "Narration item", "Character item" as *types* (the retired model), "retyping" an item — a narration↔dialog flip is a speaker assignment
- **Character paragraph** — a Paragraph with ≥1 **non-narrator** speech item: the unit of attribution selection, roll-up denominators and node status badges. One speaker assignment can switch it on or off, so a flip clears selection and reseeds counts — the same discipline a structural change follows.
- **Book Hierarchy** — in-memory `BookHierarchy` that plans structural mutations (split / merge / deletion / title insertion / item insertion) and returns a `HierarchyMutation` (ToAdd / ToDelete / ToUpdate). Node insertion, Item insertion and Volume deletion return a **`HierarchyPlan`** instead — Planned (the writes plus the `CreatedNode` and its parent), NoChange, or Refused (a `BookMutationRejection` kind and the reason) — so a refusal names why. A merge returns a **`BookMergePlan`** instead — the same writes plus `SurvivorId` and `DeletedId`, because the pair is what lets a Book View carry expansion onto the node that took the deleted one's place ([ADR 0007](../docs/adr/0007-book-mutations-reconcile-book-view-projections.md)). The deep planning module; the **Book mutation** implementations dispatch to it. _Note_: pause-**paragraph** insertion is the one structural mutation that does **not** go through it — it computes its own orders.
- **Split** — a structural mutation that creates a **new parent** node: Split Volume (at a Part), Split Part (at a Chapter), Split Chapter (at a Paragraph), Split Paragraph (at a ParagraphItem). A split never divides a node's *text*.
- **Node insertion** — a new Volume, Part, Chapter or Paragraph placed **Before** or **After** a sibling at the anchor's own level, or **At start** / **At end** of the anchor's children one level down — never two levels down. A new Volume, Part or Chapter is born **empty** (zero children; its title optional), and an empty node is filled by inserting at its start or end. A new Paragraph is never born empty — an empty Paragraph reads as a pause — so it is born holding its first speech item, unattributed. Pause paragraphs take Before/After too. A book always keeps at least one Volume: the last one cannot be deleted, so there is always an anchor to insert from.
  _Avoid_: "line" for a ParagraphItem, "add" for a structural insert
- **Structure rules** — the per-kind table of what may be inserted where: for each anchor kind (Volume, Part, Chapter, Paragraph, pause Paragraph, ParagraphItem), the placements it allows, the kind each placement creates, whether the new node needs text, and how few of a kind the book may keep (one Volume). Owned by the **Book Hierarchy**, which plans from it, and sent to the web app with the book overview so the node menu offers exactly what the planner accepts. A request the rules forbid is **refused**, never a quiet no-change.
  _Avoid_: "menu rules", "permissions" — these are domain rules, not UI or access control
- **Item insertion** — a new **Speech** ParagraphItem placed **Before** or **After** an anchor item, or **At start** / **At end** of an anchor Paragraph, always **within that one Paragraph** (never crossing into a neighbouring one). Born **unattributed** — no speaker, no voice instructions, no audio — so it is not yet a **Generatable item**, and it raises the attribution-remaining badge. Never a Pause, and never anchored on a Pause item. The user's repair for a merged two-speaker item: edit the anchor's text down, insert, paste, assign. Distinct from **Split**, which makes a new parent rather than a new sibling.

## Characters

- **Alias** — alternate name for a Character (e.g. "Lizzy" for "Elizabeth Bennet"). Stored in `CharacterAliases`. Injected into the LLM attribution prompt alongside the canonical name and matched case-insensitively when attribution resolves a name (`CharacterResolver`), so an alternate name resolves to the existing canonical Character instead of a duplicate.

## Book view

- **Book page** — the web app's reader for one Book; its row shape is the **Reader mode** ([web.md](web.md)).
- **Node menu** — the one actions menu for a Volume, Part, Chapter, Paragraph or ParagraphItem, opened from its ⋮ trigger in the structure tree or on the Book page. A node offers the same entries wherever its menu is opened: what may be done to it is a fact about the node, not about the pane.
  _Avoid_: "overflow menu", "context menu", "tree menu"
- **Placeholder title** — the label shown for a Volume, Part or Chapter whose title is missing or blank: "Untitled chapter 3", numbered by position among its siblings, and set visibly apart from a real title wherever it appears (structure tree, Book page heading, accessible names). Never stored and never narrated; renaming starts from an empty title, not from the placeholder.
  _Avoid_: "default title", "fallback title", "Chapter 3" as if it were the node's title

- **Book mutation** — one user or domain operation that changes the persisted Book, even when it touches several records or facets (a split, an accepted AI edit, a Character merge). Committed through `BookMutations.CommitAsync`, which owns per-project write serialization, the transaction, the single commit point and the revision. Returns a **Book mutation receipt**: project and mutation identity, revision, any created identity and the node holding it, the facets and identifiers *actually* affected, and structural split/merge relationships — facts, never instructions for how to reconcile. A valid operation that changes nothing is `NoChange` and consumes no revision ([ADR 0007](../docs/adr/0007-book-mutations-reconcile-book-view-projections.md)).
- **Receipt-driven refresh** — how an open view converges on a committed Book mutation; defined in [web.md](web.md). The persisted Book is authoritative, and a client view is always rebuildable from it ([ADR 0012](../docs/adr/0012-blazor-ui-removed.md)).

## Selection

- **Paragraph selection** (`SelectionStore`, web app) — the set of Character paragraphs selected on the book page for the Character Queue. Client-side only: selected paragraph ids + each one's ancestry `(VolumeId, PartId, ChapterId)`.
- **Roll-up** — a node's tri-state (Unchecked / Indeterminate / Checked) is **derived** from how many of its selectable Character paragraphs are selected vs its total. Never stored; computed on read. Selecting a node selects all (or, **unprocessed-only**, the unprocessed subset of) its Character paragraphs; additive and idempotent.
- **Book Node Level** (`BookNodeLevel { Volume, Part, Chapter }`, in Core) — the selectable triad. One enum used by the reader to scope Character-paragraph queries and by the selection roll-up.
- **Selectable node** — a Volume / Part / Chapter containing ≥1 Character paragraph. Only selectable nodes show a checkbox. The selection store learns each node's total from a `paragraph-ids` / `item-ids` read or from a loaded chapter.
- **Audio Item Selection** (`AudioSelectionStore`, web app) — the set of voiced ParagraphItems selected in Audio mode for the Audio Queue. The paragraph selection's shape at ParagraphItem granularity, in a separate store so switching mode never mixes the two. Rolls up to Chapter/Part/Volume for tri-state.
- **Generatable item** — a non-Pause ParagraphItem that can have audio generated: **missing audio** (no WAV) **and** **attribution-ready**, which with the speaker as the discriminator means simply **any speaker at all** — narration qualifies because it is stamped with the narrator, dialog once it has a Character, and only an unattributed item does not. The audio analog of an **unprocessed** attribution paragraph. The node-level "select needs audio" (`needsAudioOnly`) selects only Generatable items; an unattributed item's checkbox is disabled (not yet Generatable). A manual speaker flip, **a manual text edit or a manual delivery-cue edit** clears the item's WAV, returning it to Generatable; LLM stamping does not. A node's audio roll-up denominator is its **Voiced items**, so a needs-audio select can land on Indeterminate.
- **Voiced item** — a non-Pause ParagraphItem with a speaker to read it (any speaker at all, or any item in narrator-only mode), **whether or not it has a WAV** — a take can be regenerated. The superset of **Generatable item** (voiced *and* missing audio). What the web reader's Audio Item Selection can hold: its item checkbox is enabled for voiced items, a tree checkbox selects a node's voiced items (`item-ids`, the reader's `voicedOnly`), and its roll-up denominator counts them, so a full-node tick reads Checked.

## Node status

- **Node Status Badge** — a per-node (Volume / Part / Chapter) count of remaining work on the book page's structure tree. Three **stages**: **attribution remaining** (paragraphs with an unattributed item), **audio remaining** (paragraphs with a non-Pause item lacking a WAV — regardless of attribution), **review** (paragraphs with an `AudioReview` row in `NeedsReview`; `Dismissed` excluded). Counts **normalised to Paragraph granularity** — a paragraph qualifies for a stage if *any* item qualifies, contributing 1. All three at zero → single "done" indicator. Shown in every Reader mode.
- **Node Status roll-up** — each badge is the **cumulative** count of qualifying paragraphs beneath it (Volume ≥ Part ≥ Chapter); the same paragraph echoes up every ancestor. Held by singleton `NodeStatusService`, storing per-paragraph stage **counters** (`unattributed`, `missingAudio`, `review`) + `(Chapter, Part, Volume)` ancestry. Seeded via `IProjectReader.GetNodeStatusSeedAsync` and **never patched incrementally**: the project-status endpoint reseeds it from the database on every read, and its `Changed` pushes the corrected roll-ups to the project's hub group as `nodeStatus`.
