# Audio pipeline

Use these terms exactly in code, tests, and discussion.

- **Two-pass normalisation** — loudness normalisation to EBU R128 (`I=-16:TP=-1.5:LRA=11`) as two ffmpeg `loudnorm` calls: pass 1 measures (`print_format=json`, parsed from stderr), pass 2 applies measured values (`linear=true`). Pass-1 JSON unparseable → fall back to **single-pass** `loudnorm`; only a hard ffmpeg/exe failure → **Skipped**. Applied on the paragraph path (`NormalizeAsync`, loudness-only, skip → original WAV intact) and the upload/reference path (`NormalizeToWavAsync`).
- **`NormalizeToWavAsync`** — the upload/reference contract on `IAudioNormalizer`: input any ffmpeg-decodable format, output **always** a **Canonical WAV** (or throws). No "original" fallback; convert folded into two-pass loudnorm (its output is already WAV PCM). A loudnorm/parse failure degrades to a **bare transcode** (`-i in out.wav`, no filter); only a decode failure or **absent ffmpeg** throws (surfaced as a snackbar). Shares two-pass internals with `NormalizeAsync`.
- **Canonical WAV** — fixed output format for **all stored audio**, voice reference and paragraph item alike: **24 kHz, mono, 16-bit PCM** (`-ar 24000 -ac 1 -c:a pcm_s16le`), matching chatterbox-native rate. Applied on every ffmpeg write — `NormalizeAsync`, `NormalizeToWavAsync`, and each Audio Post-Process Step — so the TTS provider's native rate never reaches disk. The format args are **not optional**: `loudnorm` resamples internally to 192 kHz and an unqualified WAV write inherits that rate. Reference uploads accept **any** ffmpeg-decodable format (no extension allowlist — ffmpeg is the gate), always re-encoded to this spec, so stored file is always `.wav`. Normalisation runs on *every* upload incl. already-WAV (consistent levels). Only a **Skipped** normalize (ffmpeg absent/failed) stores provider-rate audio — there is no ffmpeg to convert with.
- **ParagraphItem Audio** — a generated audio file for a single ParagraphItem. Visible in `SplitAudio` only. A row shows a play button when an audio file exists; tapping opens an inline player.
- **Audio Queue** — the background pipeline generating audio for selected ParagraphItems. User adds via `AudioItemSelection`; processes one at a time using the Character's voice (Character items) or narrator voice (Narration items).
- **Audio Gen Stream** — the live per-item progression in the expandable `AudioQueueStatusBar`. `AudioQueueProcessor` publishes typed `AudioGenEvent`s to `EventBroadcaster<AudioGenEvent>`; the view accumulates one card per item, tail-scrolling to newest. Mirrors the LLM `EventBroadcaster<LlmStreamEvent>` / `LlmStreamView` pattern. Each card shows the line Character, source text, and four pipeline **phases** — audio generation, normalize, Whisper transcribe, verify — each Pending (spinner) → Done/Fail as its event arrives.
- **Phase fail vs Item failure** — a **phase fail** (normalize ✗ or verify ✗) means the audio was stored and the item completed; surfaces as an `AudioReview`. An **Item failure** (`AudioGenEvent` Failed) is a hard stop with no audio (row missing, no character, no voice, no TTS config, or exception). The card renders these distinctly: a phase ✗ on one row vs a terminal red error.
- **Audio Retry** — when an attempt's audio **fails verify** (transcript exists, `wer > WerThreshold`, Semantic Rescue didn't save it), `AudioQueueProcessor` regenerates up to **`AudioMaxAttempts`** times (app-wide `AppSettings` knob, **total** incl. first, default **1** = no retry; edited in **Audio Processing** settings). The retry loop lives **inside** one `ProcessItemAsync` call (item dequeued once; all attempts contiguous). Only **verify** failure retries — normalize ✗, transcription-infra failures, and hard Item failures never retry. Loop breaks on first verify pass or exhaustion; **only the final attempt is persisted** ({id}.wav + audio path + `AudioReview` row) — intermediate attempts generate/normalize/verify in memory and broadcast events but write nothing. Exhausted-and-failing → `MarkComplete` (verify phase fail → `AudioReview`), never `MarkFailed`. Each attempt is a **new card** — every `AudioGenEvent` carries a 1-based `Attempt`, cards keyed by `(Id, Attempt)`, attempts after the first show a **"retry N"** chip (N = Attempt − 1).
- **`IAudioItemPipeline`** — the deep seam wrapping the four audio production phases for one ParagraphItem: TTS generate → normalize → transcribe → verify (incl. Audio Retry and Semantic Rescue). Takes a **`PipelineRequest`** of resolved primitives; returns a **`PipelineResult`**. Broadcasts per-attempt `AudioGenEvent`s to `AudioGenBroadcaster`. Throws on hard unrecoverable failure (TTS/filesystem exception); the caller (`AudioQueueProcessor`) catches and publishes `Failed`. Phase fails are not exceptions — they surface in `PipelineResult` as `NormalizeOutcome.Ok = false` / `VerifyOutcome.Ok = false`. Performs exactly **one** write of its own — the **Preview Source** — which is scratch, not project state; every durable write still belongs to `IAudioResultRecorder`. In `Read2Me.Services.Audio`.
- **`PipelineRequest`** — resolved inputs to `IAudioItemPipeline`: `Folder`, `ParagraphItemId`, `SourceText` (original, for WER verify; trailing-comma substitution applied internally), `Speaker`, `VoiceInstructions`, `RefAudioPath`, `ParagraphTtsServiceConfig`, `TtsSettingsOverrideJson`, `MaxAttempts`, `WerThreshold`, `FfmpegPath`. Produced by `IAudioItemResolver` — the pipeline never loads DB rows.
- **`IAudioItemResolver`** — the seam owning the Audio Queue setup phase for one ParagraphItem: DB queries (item row, NarratorOnlyMode, voice), Voice Rule evaluation, TTS config loading, ref-audio path construction. Takes a `QueuedAudioItem`; returns a **`ResolutionResult`**. In `Read2Me.Services.Audio`. No dependency on `EventBroadcaster<AudioGenEvent>` or `AudioQueueService` — those stay in `AudioQueueProcessor`.
- **`ResolutionResult`** — what `IAudioItemResolver` returns: `Speaker` (string?), `SourceText` (string?), `Request` (`PipelineRequest?` — null on failure), `FailureReason` (string?). `Succeeded = Request is not null`. The processor publishes `ItemStarted(Speaker, SourceText)` unconditionally before branching on `Succeeded` — handles the null "row not found" case and success with one path.
- **`PipelineResult`** — what `IAudioItemPipeline` returns on success: `AudioBytes` (final attempt WAV, in-memory), `NormalizeOutcome`, `VerifyOutcome`. Callers persist `AudioBytes` and write commands from the outcome fields.
- **`IAudioResultRecorder`** — the seam durably recording a `PipelineResult`: writes `{id}.wav` under `audio/`, issues `SetParagraphItemAudioCommand` + `SetAudioReviewCommand`, applies the `AudioReviewService` cache transition (both phases ok → `Clear`; any phase fail → `Set(NeedsReview)`). Returns the audio **relative path** (`audio/{id}.wav`) so `AudioQueueProcessor` can `MarkComplete` without re-deriving the filename. Owns the filename convention. In `Read2Me.Services.Audio`. Completes the resolve → pipeline → **record** seam trio; the processor keeps only queue-mark transitions, `ItemStarted`/`Failed` publishing, and the try/catch envelope.
- **Audio Post-Process Step** — an optional, cosmetic, app-level ffmpeg step applied to paragraph-item audio **between loudness normalize and verify** (so verify hears what the listener hears). Seam: **`IAudioPostProcessStep`** (`StepId` + `ProcessAsync(wav, ffmpegPath, settingsJson, ct)`), returning **`PostProcessResult(Audio, Applied, Reason)`** — never throws, never loses audio: any failure returns the input unchanged with `Applied = false` + reason (same failure semantics as `IAudioNormalizer`). Shipped steps, in pipeline order: **silence-trim** (`AudioPostProcessStepIds.SilenceTrim`) then **consonant-soften** (`AudioPostProcessStepIds.ConsonantSoften`). Runs inside the Audio Retry loop, so each attempt re-steps its own fresh TTS output. Every step writes **Canonical WAV**. In `Read2Me.Services.Audio`.
- **Silence Trim** — the Audio Post-Process Step that strips leading and trailing silence from paragraph-item audio (TTS routinely tacks dead air on either end). One ffmpeg pass: `silenceremove` at the head, then `areverse, silenceremove, areverse` for the tail — **never `stop_periods=-1`**, which would also eat *mid*-clip silence. Settings are **raw params, no presets**: `thresholdDb` (default **−50**) and `padMs` (default **50**, deliberately kept silence, implemented as `start_silence` — not a separate `apad`). Detection is hardcoded `peak` and `start_duration=0` (trim from the first sound; a "minimum silence worth trimming" knob is not a thing anyone tunes). **Enabled by default** — unlike consonant-soften, dead air is a defect, not a taste. Guard: if the trimmed result is under **200 ms** the step **skips** (`Applied = false`, reason) and returns the input — a below-threshold clip would otherwise `silenceremove` down to nothing and get stored. An absolute floor, *not* a percentage: a legitimate trim can remove 80%+ of a short item ("Yes." after 2 s of dead air), which is exactly the case the step exists for. Trimming also makes assembly pacing deterministic — the gap between items becomes the configured Pause item, not "configured pause + whatever the TTS left behind".
- **Post-Process Step Config** — JSON list on `AppSettings.AudioPostProcessStepsJson` (`[{stepId, enabled, settings}]`, camelCase via `AudioPostProcessJson.Options`). **Step order and step existence live in code**, not in this column — the stored list supplies only `enabled` + `settings` *per id*, merged onto the code-defined default list (`AudioPostProcessStepDefaults`); ids in storage with no registered step are ignored, and steps missing from storage take their code default. So a new step needs no migration and no data edit, and there is no reorder UI to build. `settings` is **step-defined**: consonant-soften stores a **preset reference** (`{engine, preset}`), silence-trim stores **raw params** (`{thresholdDb, padMs}` — one obvious behaviour and a two-field form; the preset indirection existed only because soften's chain tuning was a research output that had to reach existing rows). The preset reference is not a snapshot — raw params (`adynEq`/`deesser` objects) serialize only when `preset` is `"custom"`, so preset tuning fixes in code reach existing rows. Preset ladders live in `ConsonantSoftenPresets` (Light/Medium/Strong; adynEQ threshold held in **dB**, converted to linear for ffmpeg). Missing row/column/entry or corrupt JSON ⇒ consonant-soften **disabled** with defaults (adynEQ, Strong). Read/written by `AudioProcessingSettingsService.Get/SetPostProcessStepsAsync` (single-row upsert + `OnChanged`).
- **`IAudioPostProcessStepCatalog`** — maps stored step configs to registered `IAudioPostProcessStep` instances; returns **enabled steps in code-defined order** (silence-trim → consonant-soften), each paired with its raw settings JSON (`EnabledPostProcessStep`). Configs with no registered step are skipped. Mirrors `ITextProcessingStepCatalog` on the audio side.
- **Preview Source** — a ParagraphItem's audio as it is *after* loudness normalise but *before* any Audio Post-Process Step. The stored `{id}.wav` cannot play this role: post-process runs before verify, so what lands on disk is **already stepped**, and filtering it again for an A/B preview stacks a step on itself (a Strong-vs-Strong comparison the user reads as off-vs-draft). `AudioItemPipeline` parks the Preview Source on every attempt that normalises; the kept attempt is the last writer, so the cached bytes always match the stored WAV. Never written when normalize fails (no step ran, and the audio is provider-rate). A cache failure is logged and swallowed — the item still completes.
- **`IPreviewSourceCache`** — the capped rolling store of Preview Sources, in `<workspace>/.preview-src/` as `{folderName}__{itemId}.wav` (id is fixed-length and parsed from the right, so a folder name containing `__` cannot shift the split). Keeps the newest **50** by last-write time, evicting on write; no background job. Dot-prefixed so `ListProjectFolders` skips it (it excludes **all** dot-prefixed dirs) and the static-file provider will not serve it — the Original player reads it through the `/preview-source/{folder}/{id}` endpoint instead. Hands out **bytes** (`TryReadAsync`) to the renderer and a **path** (`TryGetPath`) only to the endpoint, which must serve it as a file. Because `ProjectFolderId` has an implicit `string` conversion the type is not itself a gate: **`ProjectFolderId.TryParse`** is — it refuses anything that is not a bare path segment, and the endpoint parses the route value through it before the cache ever builds a path. In `Read2Me.Services.Audio`.
- **A/B preview** — a post-process settings card auditions **draft** (unsaved) settings against a real item: `IRecentAudioSampleFinder` lists the cached Preview Sources (newest first, so the picker walks one small dir rather than every project's `audio/`), and `IAudioPostProcessPreviewRenderer` runs **one named step** (`stepId`) over the chosen item's Preview Source, parking the result in `AudioPreviewStore` under a circuit-minted token. One step, never the enabled chain — the card is tuning *its* step. The draft's `enabled` flag is ignored: auditioning a step you have not turned on yet is the whole point. Both players are therefore the same unprocessed audio — one filtered, one not. Used by the consonant-soften card and the silence-trim card (which also shows **removed ms**, arithmetic on the Canonical WAV byte lengths — `(bytes − 44) / 48` ms, at 48 000 bytes/s — no prober call; the queue's `PostProcessed` event stays free of a per-item millisecond count nobody would act on). An item is offerable only while its Preview Source survives; existing audio generated before the cache existed is not previewable, and cannot be (the filter is not invertible).
- **`NormalizeOutcome`** — phase result in `PipelineResult`: `Ok` (bool), `Reason` (string?).
- **`VerifyOutcome`** — phase result in `PipelineResult`: `Ok` (bool), `Wer` (double?), `Reason` (string?), `Transcript` (string?), `Rescued` (bool).
- **Word-level alignment** — an ordered transcription of spoken words with a start and end offset for each word. It is a required transcription capability wherever precise correspondence between generated audio and text is needed.

## Sentence chunking

- **Sentence Chunking** — splitting a ParagraphItem's text into sentences, synthesising each separately, then stitching per-sentence audio into one item-level WAV. Long single-call text can peak / artifact; per-sentence calls avoid it. Applied transparently inside the TTS layer — the rest of the pipeline (normalize, store one `{id}.wav`, Whisper verify against full source) is unchanged. Verify scores the whole stitched item, not per sentence.
- **`SentenceChunkedTtsClient`** — the decorator over `IParagraphTtsClient` owning chunking. **Self-gates**: when `SentenceSplitEnabled` is off it passes text straight through. Wired by `ParagraphTtsClientResolver` so every TTS type is wrapped and `AudioQueueProcessor` stays unaware. One chunk (or short item) stitches to a byte-identical passthrough.
- **Sentence Pause** (`SentencePauseMs`) — silence inserted **between** adjacent sentences when stitching (N chunks → N−1 gaps; no leading/trailing silence). Zero-PCM samples spliced into the WAV `data`.
- **Min chunk** (`SentenceMinChunkChars`) — a sentence fragment shorter than this merges into its neighbour, so titles / short exclamations don't become micro-chunks. Internal tuning knob, not surfaced in UI.
- **Chunk failure** — if any one sentence's TTS throws, the whole item fails (decorator throws; processor's catch marks it an Item failure). No partial/gappy audio is stored.
