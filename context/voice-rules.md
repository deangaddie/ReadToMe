# Voice rules

Use these terms exactly in code, tests, and discussion.

- **Voice** — a single synthesizable voice owned by a Character (uploaded reference audio or generated). A Character has many Voices. No "default voice" flag; the default is expressed by the Character's **default Voice Rule**.
- **Ready Voice** — a Voice usable by the TTS pipeline: `AudioFileName` is non-empty. Same predicate the audio pipeline gates on (`AudioItemResolver`: a Voice with empty `AudioFileName` → "has no reference audio" failure). Definition is in-memory only — does **not** stat the file on disk; chosen so the Characters-tab "ready" count can never disagree with playback. A Generated Voice with a design prompt but no synthesised audio yet is **not** ready.
- **Reference Limit** — the app-wide bound on a Voice's reference audio, set to the tightest limit across every supported TTS provider. It applies to the reference wherever it was created, because the Voice outlives the active provider. **Hard limit**: 30 s (and 5 MiB); anything longer is rejected at upload or fails generation. **Soft limit**: 15 s; a reference over it is kept, with a warning. The limits are enforced where a reference is made (upload, voice design) and never by trimming at synthesis time, because trimming the audio would break its transcript. Being over the soft limit does not stop a Voice being a **Ready Voice**.
  In code: `ReferenceLimit` (`Read2Me.Services.Audio`), checked once at `FileAudioPipeline.StoreAsync` — the chokepoint both upload and voice design store through — on the normalised audio's duration as `WavHeader` reads it, so the check and the voice list never disagree at a limit. A refused reference changes nothing on disk. An upload over the hard limit is rejected ("trim it and upload again"); a generated take over it fails with "shorten the voice-design sample text". `VoiceDto` carries `referenceSeconds` and `referenceWarning` (set over the soft limit). The hard limit pairs with audio.cpp's VoxCPM2 `audiovae_encoder_sample_capacity` (30 s) and its 5 MiB inline-reference cap; raise one and the other must follow.
  Voice design keeps takes short by construction: the **sample text** every designed voice speaks is capped at 300 characters (`VoiceDesignSettingsService.MaxSampleTextLength`), and the built-in one is 29 words.
  _Avoid_: "max reference length" for a per-provider figure — per-provider caps feed this limit, they are not the limit.
- **Voice Rule** — an ordered, per-Character rule selecting which **Voice** to use over a **position range**. A Character owns an ordered list. Stored in `VoiceRules`. Fields: target `VoiceId`, fractional `Rank` (BINARY-collated order key), `IsDefault`, and a `From`/`To` bound pair, each a nullable `(VoiceAnchorLevel Level, Guid NodeId)`.
- **Default Voice Rule** — every Character with ≥1 Voice has exactly one rule with `IsDefault = true`. Anchors null (matches whole story), pinned top (lowest `Rank`), **not deletable or reorderable**. Created automatically when the first Voice is added (that voice becomes its target). "Update the default voice" = repoint the default rule's `VoiceId`. Deleting its target Voice repoints to the oldest remaining Voice; deleting the last Voice deletes the default rule too.
- **Position** — an audio item's absolute place: lexicographic tuple `(Volume.Order, Part.Order, Chapter.Order, Paragraph.Order, ParagraphItem.Order)` of sibling-scoped `Order` keys up its ancestry. Compared tuple-wise (Volume first).
- **Anchor** (`VoiceAnchorLevel { Volume, Part, Chapter, Paragraph, ParagraphItem }`) — a Voice Rule bound is `(Level, NodeId)`, resolving to a Position **span**: `From` → subtree minimum, `To` → subtree maximum. `From = To = chapterNode` ⇒ whole chapter subtree. `From` set, `To` null ⇒ open-ended forward. Both null ⇒ matches everything (default rule).
- **Voice Rule evaluation** — rules evaluated **top to bottom by `Rank` ascending; last passing rule wins**. A rule passes when the item's Position falls inside its resolved `[from, to]` span. The default rule always passes (always a result). Pure `VoiceRuleEvaluator` (no DB — ordered rules + item Position → `VoiceId`) owns the algorithm; **`VoiceResolver`** owns the data loading. The resolved speaker (after `NarratorOnlyMode` / Narration → Narrator substitution) is the item's **effective Character**, whose rules are used — the Narrator runs through the same evaluator.
- **Effective Character** — the Character whose Voice Rules and Voices drive an item. Dialog: the item's own Character. Narration (and every item under `NarratorOnlyMode`): the substitution's target, resolved through **`NarratorIdentity`** — the **linked character** when a [narrator link](attribution.md) is set, the seed Narrator row otherwise. So a linked character's own Voice Rules drive narration as well as its dialog, positional rules included, and the seed Narrator row's rules go **dormant while linked, not deleted** — they wake unchanged on unlink, with no audio invalidation. `AudioItemResolver` names the effective Character in its speaker string and its "No default voice for …" failure.
- **`VoiceResolver`** (`IVoiceResolver`, `Read2Me.Services.Voice`) — the single seam answering "which Voice plays each of these items?" Takes a `folder` + a **set** of `ParagraphItem` ids; returns `Dictionary<itemId, Guid?>` (resolved `VoiceId`, null = none). Reads `NarratorOnlyMode` **and the narrator link from the same `Projects` query** (no extra round-trip), applies the substitution to get each item's **effective Character**, then in a **constant** ~8 queries (regardless of item/character count) batch-loads item positions, each effective character's rules once, and every rule's anchor node-orders once globally, running `VoiceRuleEvaluator` per item. Replaces the former N+1 pair (`GetVoiceRuleInputsAsync` + `GetResolvedVoiceNamesAsync` on `ProjectReader`). Two consumers: `AudioItemResolver` (single-item set → `VoiceId`, then loads the full Voice itself) and the Resolved voice preview (batch). Sister `ResolveNamesAsync` adds one batched `Voices` name lookup over distinct resolved ids for the preview. Depends on `ProjectDbSession`. Per-rule anchor→span transform delegated to pure **`AnchorSpanResolver`**.
- **`NodeOrderTables`** — resolved order data the pure span layer needs: five per-level lookups (Volume/Part/Chapter/Paragraph order strings, full `StoryPosition`s for ParagraphItem anchors) batch-loaded by `VoiceResolver`. Owns `TryResolve(level, nodeId, isMin, out StoryPosition)` — pads a node's known orders with `StoryPosition.MinKey`/`MaxKey` to form subtree-min (`isMin`) or subtree-max bound, reporting a missing node (**dangling anchor**) via false. Single home of the min/max sentinel convention.
- **`AnchorSpanResolver`** — pure module turning one Voice Rule + a `NodeOrderTables` into a `RuleInput`: resolves `From`/`To` via `TryResolve`, combines into the dangling flag + resolved span, carries through `VoiceId`/`Rank`/`IsDefault`. No DB. Extracted from `VoiceResolver`'s former inline span loop so the span/dangling logic is unit-testable. Feeds `VoiceRuleEvaluator`.
- **Dangling anchor** — a Voice Rule whose anchor `NodeId` no longer exists (any structural change — split / merge / **reread** — regenerates node ids; reread preserves Characters/Voices but clears all Volume…ParagraphItem rows). **Skipped** at evaluation (not-passing) and **flagged in the UI** for re-anchoring — never silently deleted. (Cascade-delete applies only when the rule's _target Voice_ is deleted.)
- **Voice Rule editor** — the per-Character Voice Rules section in `CharacterDetailPanel`, below the voices list. Reordered with up/down arrows (default pinned top). The per-voice "set as default" star repoints the default rule's target. New rules via a **mode-based editor** — _From here on_ (`From = node, To = null`) or _Just this node_ (`From = To = node`); _Range_ mode deferred. Anchor node chosen via **cascading dropdowns** (Volume → Part → Chapter → Paragraph → ParagraphItem; deepest chosen wins). Creation goes through UI-agnostic `CreateVoiceRuleCommand` for future "add rule from book selection" reuse. A dangling rule shows a warning + "re-anchor" ("(missing node)").
- **Resolved voice preview** — `SplitAudio` view shows, per Character item, the Voice that _will_ play, computed by the same **`VoiceResolver`** (`ResolveNamesAsync`) the audio pipeline uses, so preview and playback cannot drift. Under a Narrator link, narration is labelled `Narrator → Linked Character` while that Character's dialog keeps the plain Character name; this preview-only arrow explains why both use the linked Character's Voice Rules. Unlinked display is unchanged. A dangling rule simply doesn't match; the item shows whichever rule wins (often the default).
