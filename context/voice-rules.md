# Voice rules

Use these terms exactly in code, tests, and discussion.

- **Voice** — a single synthesizable voice owned by a Character (uploaded reference audio or generated). A Character has many Voices. No "default voice" flag; the default is expressed by the Character's **default Voice Rule**.
- **Voice Rule** — an ordered, per-Character rule selecting which **Voice** to use over a **position range**. A Character owns an ordered list. Stored in `VoiceRules`. Fields: target `VoiceId`, fractional `Rank` (BINARY-collated order key), `IsDefault`, and a `From`/`To` bound pair, each a nullable `(VoiceAnchorLevel Level, Guid NodeId)`.
- **Default Voice Rule** — every Character with ≥1 Voice has exactly one rule with `IsDefault = true`. Anchors null (matches whole story), pinned top (lowest `Rank`), **not deletable or reorderable**. Created automatically when the first Voice is added (that voice becomes its target). "Update the default voice" = repoint the default rule's `VoiceId`. Deleting its target Voice repoints to the oldest remaining Voice; deleting the last Voice deletes the default rule too.
- **Position** — an audio item's absolute place: lexicographic tuple `(Volume.Order, Part.Order, Chapter.Order, Paragraph.Order, ParagraphItem.Order)` of sibling-scoped `Order` keys up its ancestry. Compared tuple-wise (Volume first).
- **Anchor** (`VoiceAnchorLevel { Volume, Part, Chapter, Paragraph, ParagraphItem }`) — a Voice Rule bound is `(Level, NodeId)`, resolving to a Position **span**: `From` → subtree minimum, `To` → subtree maximum. `From = To = chapterNode` ⇒ whole chapter subtree. `From` set, `To` null ⇒ open-ended forward. Both null ⇒ matches everything (default rule).
- **Voice Rule evaluation** — rules evaluated **top to bottom by `Rank` ascending; last passing rule wins**. A rule passes when the item's Position falls inside its resolved `[from, to]` span. The default rule always passes (always a result). Pure `VoiceRuleEvaluator` (no DB — ordered rules + item Position → `VoiceId`) owns the algorithm; **`VoiceResolver`** owns the data loading. The resolved speaker (after `NarratorOnlyMode` / Narration → Narrator substitution) is the Character whose rules are used — the Narrator runs through the same evaluator.
- **`VoiceResolver`** (`IVoiceResolver`, `Read2Me.Services.Voice`) — the single seam answering "which Voice plays each of these items?" Takes a `folder` + a **set** of `ParagraphItem` ids; returns `Dictionary<itemId, Guid?>` (resolved `VoiceId`, null = none). Reads `NarratorOnlyMode`, applies Narrator substitution for each item's **effective Character**, then in a **constant** ~8 queries (regardless of item/character count) batch-loads item positions, each effective character's rules once, and every rule's anchor node-orders once globally, running `VoiceRuleEvaluator` per item. Replaces the former N+1 pair (`GetVoiceRuleInputsAsync` + `GetResolvedVoiceNamesAsync` on `ProjectReader`). Two consumers: `AudioItemResolver` (single-item set → `VoiceId`, then loads the full Voice itself) and the Resolved voice preview (batch). Sister `ResolveNamesAsync` adds one batched `Voices` name lookup over distinct resolved ids for the preview. Depends on `ProjectDbSession`. Per-rule anchor→span transform delegated to pure **`AnchorSpanResolver`**.
- **`NodeOrderTables`** — resolved order data the pure span layer needs: five per-level lookups (Volume/Part/Chapter/Paragraph order strings, full `StoryPosition`s for ParagraphItem anchors) batch-loaded by `VoiceResolver`. Owns `TryResolve(level, nodeId, isMin, out StoryPosition)` — pads a node's known orders with `StoryPosition.MinKey`/`MaxKey` to form subtree-min (`isMin`) or subtree-max bound, reporting a missing node (**dangling anchor**) via false. Single home of the min/max sentinel convention.
- **`AnchorSpanResolver`** — pure module turning one Voice Rule + a `NodeOrderTables` into a `RuleInput`: resolves `From`/`To` via `TryResolve`, combines into the dangling flag + resolved span, carries through `VoiceId`/`Rank`/`IsDefault`. No DB. Extracted from `VoiceResolver`'s former inline span loop so the span/dangling logic is unit-testable. Feeds `VoiceRuleEvaluator`.
- **Dangling anchor** — a Voice Rule whose anchor `NodeId` no longer exists (any structural change — split / merge / **reread** — regenerates node ids; reread preserves Characters/Voices but clears all Volume…ParagraphItem rows). **Skipped** at evaluation (not-passing) and **flagged in the UI** for re-anchoring — never silently deleted. (Cascade-delete applies only when the rule's *target Voice* is deleted.)
- **Voice Rule editor** — the per-Character Voice Rules section in `CharacterDetailPanel`, below the voices list. Reordered with up/down arrows (default pinned top). The per-voice "set as default" star repoints the default rule's target. New rules via a **mode-based editor** — *From here on* (`From = node, To = null`) or *Just this node* (`From = To = node`); *Range* mode deferred. Anchor node chosen via **cascading dropdowns** (Volume → Part → Chapter → Paragraph → ParagraphItem; deepest chosen wins). Creation goes through UI-agnostic `CreateVoiceRuleCommand` for future "add rule from book selection" reuse. A dangling rule shows a warning + "re-anchor" ("(missing node)").
- **Resolved voice preview** — `SplitAudio` view shows, per Character item, the Voice that *will* play, computed by the same **`VoiceResolver`** (`ResolveNamesAsync`) the audio pipeline uses, so preview and playback cannot drift. A dangling rule simply doesn't match; the item shows whichever rule wins (often the default).
