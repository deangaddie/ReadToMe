# Project history

Use these terms exactly in code, tests, and discussion.

- **History** — a project's ordered, append-only record of the changes a user has made to it. Each entry is a **History step**. Nothing is ever removed from History by using it: a Restore adds a step, it never cuts later steps off. History is project-wide; there is no per-item history or per-item rollback.
  _Avoid_: "undo stack", "versions" (reserved for a later, user-named step), "checkpoint" (already a Pipeline term, see [web.md](web.md))
- **History step** — one user action, however many records it touches: an accepted Edit with AI is one step, not one per paragraph; one attribution run is one step, not one per paragraph it commits. A step is labelled by what the action was and what it touched, and it fixes the whole **project state** as it stood after that action.
  _Avoid_: "microversion" (Onshape's word), "revision" (the in-memory Book mutation receipt counter, [book-structure.md](book-structure.md))
- **Step scope** — what opens and closes a History step: everything committed while it is open is that one step. Each state-changing request opens one, labelled in user terms ("Edit with AI"), so one request is at most one step whichever client sent it; a Background run and a Restore open their own. A change committed with no scope open is a step of its own. The step's **what changed** ("4 paragraphs in Chapter 3") is written from the counts and places its commits report.
  _Avoid_: "transaction" (one commit, of which a step may hold several), "origin" (the echo-suppression id, which does not group steps)
- **Background run** — one project's busy period of the Character Queue or the voice batch: from idle to busy until it drains, is cancelled or fails. Enqueuing more while busy extends it. A background run's work is one History step; only a commit from outside it (a user's gesture, in practice) splits it into parts ("part 1", "part 2"), and results it commits never do. Background runs that overlap share their step.
  _Avoid_: "run" alone (collides with the LLM **Run outcome**, [llm.md](llm.md)), "batch" for the attribution side
- **Project state** — everything a History step fixes: the book content, characters and aliases, voices and their reference audio, voice rules, narrator and project settings, cover, metadata and source book file. It is the user's *choices*. Generated per-item TTS takes and their audio reviews are results, and Pipeline checkpoints are progress; neither is state. App-wide settings are outside it.
- **State file** — a file that is part of Project state: a voice's reference audio and the voice editor's stored original of it, the cover, the source book file. Each History step records its **file list** (each state file's path to the hash of its content, kept in the History blobs), so a step's files read and restore as they were. An item's TTS take is a result, never a state file; neither is a Preview Source.
- **View a step** — open the whole project read-only as it stood at a History step. Changing anything requires a Restore first.
- **Restore** — make an older History step's project state the current one by adding a **new** History step whose state equals it; the steps after the restored one stay in History and can themselves be restored. A Restore changes the project exactly as the equivalent edits would: an item whose text or speaker changes has its audio discarded and needs generation, and an item brought back by a Restore returns without audio.
  _Avoid_: "rollback" as a destructive operation, "revert", "stale take" (mismatched audio is discarded, as after an edit)
