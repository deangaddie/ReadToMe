# Audiobook assembly & live-event infra

Use these terms exactly in code, tests, and discussion.

## Audiobook assembly

- **Audiobook Assembly** — combining every ParagraphItem's WAV, plus silence for Pause items, into one **m4b** (AAC) per project with embedded **chapter markers**, **cover**, metadata. Triggered by a single **Assemble** toolbar button (always visible, all view modes). One project = one assembly. Output: `{projectFolder}/output/{sanitized BookTitle}.m4b`, overwritten each run. Distinct from the per-item Audio Queue — a **single long job**, not a queue.
- **Assembly Service** (dedicated job runner, not `QueueWorker<T>`) — a **single-flight** background task started by the Assemble button. **Gated**: disabled while an assembly runs *and* while the Audio Queue has in-flight items for that project (output would be stale). **Cancellable** via the status bar (mirrors `AudioQueueStatusBar`). Reads a **DB snapshot at start** (`GetAssemblyManifestAsync`) so mid-run edits don't corrupt output.
- **Assembly precondition** — **blocked** unless every non-Pause item across the book has a WAV. Reuses the node-status **audio-remaining** count. Pauses need no audio. No gappy/placeholder output; button disabled with "N items still need audio".
- **Assembly Manifest** (`IProjectReader.GetAssemblyManifestAsync(folder)`) — the ordered item stream the assembler walks, in **Position** order (same tuple as voice rules). Each entry carries item id, `ItemType`, audio relative path (null for pauses), and section ancestry (Volume/Part/Chapter ids + titles) for chapter markers.
- **Pause durations** (`AppSettings`, per-kind ms) — Pause items store only a *kind*; the assembler maps kind→ms: `VolumePauseMs` (4000), `PartPauseMs` (3000), `ChapterPauseMs` (2500), `ParagraphPauseMs` (800), `PauseMs` (500). Editable in **Audio Processing** settings. The longer Volume/Part/Chapter pauses separate sections inline.
- **Silence segments** — concat needs silence as real files in **Canonical reference WAV** format. Generated via ffmpeg `anullsrc` (`-f lavfi -i anullsrc=r=24000:cl=mono -t {sec} -c:a pcm_s16le`), **cached per distinct ms** (~5 files max).
- **Concat assembly** — one ffmpeg pass over the **concat demuxer**: a list interleaving item WAVs and silence segments, decoded and encoded to **AAC** once (`-c:a aac -b:a 64k -ac 1 -ar 24000`), muxed to m4b. Chapter timestamps from per-input durations (item WAVs probed via ffprobe; silence known exactly). Single encode = best quality + correct timestamps.
- **Chapter markers** — each **section** (Volume / Part / Chapter) becomes its own m4b chapter; the marker lands at the start of that section's first audio item (its **title narration** — titles are ordinary Narration items, see `TitleInserter`). m4b chapters are **flat**; nested levels each emit a marker labelled by node title (fallback "Chapter N"). Written via an **ffmetadata** file (`-f ffmetadata` `[CHAPTER]` blocks + `-map_metadata`).
- **m4b metadata + cover** — standard tags: `title`=BookTitle, `artist`+`album_artist`=Author, `album`=BookTitle, `genre`=Audiobook. Cover (`Project.CoverImage`, relative jpg, nullable) embedded as `-c:v mjpeg -disposition:v attached_pic`; **null cover → no cover stream** (not an error).
- **Assembly progress** — coarse **phases** broadcast to a status bar (gather manifest → generate silence → probe/build concat → **encode m4b** → finalize). The encode phase shows a **live %** parsed from ffmpeg stderr `time=` against total duration. Mirrors the `EventBroadcaster<AudioGenEvent>` / status-bar pattern; no per-item cards.
- **Assembly failure** — encode writes to `{title}.m4b.tmp`, **atomic rename** on success, temp deleted on failure (never a truncated m4b). A hard ffmpeg/disk failure broadcasts a **terminal Failed** event with the ffmpeg stderr tail (red status bar); **ffmpeg-absent** reuses the normalizer's "set the path in Audio Processing settings" message.

## Live-event infra & voice batch

- **`EventBroadcaster<T>`** — the generic singleton bridge for live event streaming: a scoped producer calls `Publish`; a singleton-subscribed Blazor view receives via `Event` (marshalled with `InvokeAsync(StateHasChanged)`). One transport carries every event family (`LlmStreamEvent`, `AudioGenEvent`, `AssemblyEvent`, `VoiceBatchEvent`); each a distinct closed-generic singleton. Replaces the former per-feature broadcaster shells.
- **`VoiceBatchRunner`** — the singleton running one Voice Batch sweep (characters-tab "generate prompts / audio for all") over a Sweep Phase, owning the invariant envelope: the async scope, the foreach, cancellation, live counters (`Total`/`Processed`/`Failed`/`CurrentVoiceName`/`CurrentOperation`) + locking, and the `BatchStarted → BatchProgress → VoiceUpdated → BatchCompleted/BatchCancelled` sequence published to `EventBroadcaster<VoiceBatchEvent>`. The UI binds its polled state and calls `Cancel()`. Pure inner `RunPhaseAsync<TWork>` takes an already-built `PhaseDeps` (no scope creation) and is the unit under test.
- **Sweep Phase** (`ISweepPhase<TWork>`) — one voice-batch phase = a filter (`PlanAsync` → work list, free to issue pre-step DB writes deciding what to process) + a per-item step (`RunStepAsync` → a `PhaseStepOutcome` of ok/soft-fail + `VoiceUpdated` payload) + a `DisplayName`. The phase owns what-to-process and what-to-do; `VoiceBatchRunner` owns the envelope. Two phases today: `GeneratePromptsPhase`, `GenerateAudioPhase`.
