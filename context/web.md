# Web front end

Use these terms exactly in code, tests, and discussion. Background: [ADR 0014](../docs/adr/0014-native-web-front-end-replaces-angular.md); how-to: [docs/agents/web.md](../docs/agents/web.md).

- **Web app** — the front end in `src/Read2Me.Web` (custom elements on Bun), served by the .NET host at `/app` from the bundle `bun run build` emits into `src/Read2Me.App/wwwroot/app`. `/` redirects to it. It owns no data: the host, its workspace and the API do.
- **Live hub** — the SignalR endpoint `/hubs/live` the web app subscribes to. The **Live relay** (`LiveRelay`, `Live/`) is the host-side bridge that turns in-process events (queue snapshots, node status, receipts, watchdog, streams) into hub pushes; the **event family** is the hub method name (`queue`, `nodeStatus`, `itemStatus`, `receipt`, `assembly`, `voiceBatch`, `watchdog`, `serviceStatus`, `preflight`, `llm`, `audioGen`, `throughput`, `settingsChanged`, `bookEdit`, `llmTest`, `history`) and each payload carries a `kind` discriminator. Project-scoped families go to the **project group** a client joins with `JoinProject(folder)`; stream families to a **stream group** (`JoinStream(kind)`).
- **Live snapshot** — what `GetSnapshot()` returns on connect and reconnect: the last value of every snapshot-shaped family, so a late or reconnected client needs no replay.
- **Receipt-driven refresh** — the web app never patches a Book from a command's response; it reloads the affected view from the `receipt` the hub pushes (ADR 0007's receipts, consumed by the client). The reader's **receipt plan** (`receipt-plan.ts`) decides what to reload for a receipt (tree, chapter rows, status).
- **Reader mode** — the book page's row shape: `read` (prose only), `speakers` (per-item speaker chips, paragraph selection for attribution), `audio` (per-item voice preview, audio status, playback, item selection for audio). Carried in the URL as `?mode=`.
- **Pipeline step** — one row of the overview's stepper, the ordered journey a project walks from import to export; exactly one step is **next** (`aria-current="step"`), and each step's actions are the gestures that advance it. Nine rows (`import`, `structure`, `speakers`, `text`, `voices`, `titles`, `pauses`, `audio`, `export`), derived in one place (`ProjectStore.pipeline` over the pure `derivePipeline`) from the project status roll-up, the hub's running flags and the newest build; a step's **state** is `notStarted`, `remaining`, `running`, `unconfirmed`, `done`, `confirmed`, `skipped` or `stale`, and the next step alone hints how many later steps are already done. A step's **checkpoint** is how it counts as done: **derived** (computed from project status) or **confirmed** (the user ticks it off per project, stored by the host), for steps like "structure is sorted" that no data can decide; a step may hold both, done when every condition holds. A confirmed checkpoint is **confirmed**, **skipped** (a conditional step the book does not need) or **stale** (a later Book mutation disturbed what was confirmed; the step asks to be reconfirmed, never blocks). A **conditional** step is one a book may not need ("check, then do if needed"). A checkpoint guides, it never gates: no action is disabled by one. A **callout** is a state-driven banner on a step's Overview row and at the top of its destination page, cleared when its condition clears or the step is confirmed; an **advice line** is the one sentence an out-of-order action shows before it is clicked (muted under the action, as a menu entry's second line, or above the button of the action's own dialog), never inside a confirm; a **permanent-change confirm** is the confirm a button or menu entry shows before a change that one more action cannot reverse (a dialog the user filled in counts as its own confirm); a **blocked reason** is the sentence a long-lived disabled control carries as a tooltip (none for a momentary busy). The **next-step pill** is the app bar's compact indicator of the next Pipeline step and its primary action. **Help text** is the per-step explanation authored as markdown in the repo (`docs/guide/`, one file per step) and shown from the step's Overview row; it names controls in prose and never links into app actions. _Avoid_: journey, stage, wizard — there is one term for the rows and it is Pipeline step.
- **Activity centre** — the shell's background-work surface: the **activity bar** pill(s) in the app bar, the **activity drawer** with Jobs / Streams / Services tabs, and the **stream feed** (LLM turns, audio cards) for the stream a user chose to watch.
- **Preflight sheet** — the bottom sheet `Preflight.ensureReady(taskKind)` opens when a task's AI services are not all ready: services to start, GPU conflicts to stop, per-service stages from the `preflight` family. Every AI action goes through `ensureReady`; nothing else decides readiness.
- **Setup check** — the one report on whether the install is sound: every dependency the app needs (the Workspace, ffmpeg, the active LLM, TTS, voice design, transcription and similarity configs, the docker AI services) gets a **check** with one result — **Passed**, **Failed**, **Not confirmed** (the Quick check could not tell without starting something), **Not run** (cancelled, or blocked by an earlier failure) or **Not used** (no active config needs it) — and every check says what the app expected and what it found, and carries a **fix hint**: where to change it. A check may also carry a **note**, which never changes its result (e.g. config and the app disagreeing on a value that still works). It comes in two tiers: the **Quick check** reads configuration and the state of what is already running and never starts, stops or switches anything; the **Full check**, run only when asked, starts each service an active config uses and loads each model it names, then puts everything back as it found it, except a container whose check failed, which it leaves as it is for its logs. It runs by itself, is pointed out on first load, and can be run again at any time. It differs from the Preflight sheet, which readies one task's services right now; the Setup check asks whether everything is set up at all. _Avoid_: health check (the container probe), diagnostics, self-test.
- **Managed service status** — the last observed status of one docker-managed AI service (`Ready`, `Starting`, `Stopped`, `Recovering`, `Down`, `NotFound`, `Unknown`), fed by the `serviceStatus` family into `AiServicesStore`; every status chip in the web app reads that one source.
- **`r2m-*` component library** — the shared elements, partials and CSS primitives under `src/app/ui`: elements are named `r2m-<name>`, and a partial puts `r2m-<name>` on its root as a class; those names, BEM classes and `data-*` attributes are the E2E handles. Feature code builds from these, and calls the API only through `ApiClient`.
- **Web E2E** — the browser tests under `src/Read2Me.E2eTests/Tests/Web` on `E2eTestBase`: the in-proc host with fake AI and seeders, driving `/app/...`; skipped, never failed, when no bundle has been built.
