# Web front end (Angular)

Use these terms exactly in code, tests, and discussion. Background: [ADR 0008](../docs/adr/0008-second-front-end-angular-beside-blazor.md); how-to: [docs/agents/web.md](../docs/agents/web.md).

- **Web app** — the Angular front end in `src/Read2Me.Web`, served by the .NET host at `/app` from the bundle `npm run build` emits into `src/Read2Me.App/wwwroot/app`. The **Blazor UI** is the original front end at `/`. Both run on one host, one workspace, one API; neither owns the data.
  _Avoid_: "the new UI" / "the old UI" — name the framework.
- **Live hub** — the SignalR endpoint `/hubs/live` the web app subscribes to. The **Live relay** (`LiveRelay`, `Live/`) is the host-side bridge that turns in-process events (queue snapshots, node status, receipts, watchdog, streams) into hub pushes; the **event family** is the hub method name (`queue`, `nodeStatus`, `itemStatus`, `receipt`, `assembly`, `voiceBatch`, `watchdog`, `serviceStatus`, `preflight`, `llm`, `audioGen`, `throughput`, `settingsChanged`, `bookEdit`, `llmTest`) and each payload carries a `kind` discriminator. Project-scoped families go to the **project group** a client joins with `JoinProject(folder)`; stream families to a **stream group** (`JoinStream(kind)`).
- **Live snapshot** — what `GetSnapshot()` returns on connect and reconnect: the last value of every snapshot-shaped family, so a late or reconnected client needs no replay.
- **Receipt-driven refresh** — the web app never patches a Book from a command's response; it reloads the affected view from the `receipt` the hub pushes (ADR 0007 applied to a second client). The reader's **receipt plan** (`receipt-plan.ts`) decides what to reload for a receipt (tree, chapter rows, status).
- **Reader mode** — the book page's row shape: `read` (prose only), `speakers` (per-item speaker chips, paragraph selection for attribution), `audio` (per-item voice preview, audio status, playback, item selection for audio). Carried in the URL as `?mode=`.
- **Pipeline step** — one row of the overview's stepper (`import`, `cast`, `attribute`, `voices`, `audio`, `export`), computed from the project status roll-up; exactly one step is **next** (`aria-current="step"`), and each step's actions are the gestures that advance it.
- **Activity centre** — the shell's background-work surface: the **activity bar** pill(s) in the app bar, the **activity drawer** with Jobs / Streams / Services tabs, and the **stream feed** (LLM turns, audio cards) for the stream a user chose to watch. It replaces the Blazor StatusDock.
- **Preflight sheet** — the bottom sheet `Preflight.ensureReady(taskKind)` opens when a task's AI services are not all ready: services to start, GPU conflicts to stop, per-service stages from the `preflight` family. Every AI action goes through `ensureReady`; nothing else decides readiness.
- **Managed service status** — the last observed status of one docker-managed AI service (`Ready`, `Starting`, `Stopped`, `Recovering`, `Down`, `NotFound`, `Unknown`), fed by the `serviceStatus` family into `AiServicesStore`; every status chip in the web app reads that one source.
- **`r2m-*` component library** — the shared components under `src/app/ui` (import from `@app/ui`): every one has selector `r2m-<name>`, host class `r2m-<name>` (the E2E handle; lint-enforced) and a story on `/app/styleguide`. Feature code uses these instead of raw Material chips, snack bars or `HttpClient`.
- **Web E2E** — the browser tests under `src/Read2Me.E2eTests/Tests/Web` on `WebE2eTestBase`: the same in-proc host, fakes and seeders as the Blazor tests, driving `/app/...`; skipped, never failed, when no bundle has been built.
- **Parity checklist** — `.scratch/angular-frontend/parity.md`: every Blazor UI function with the web route that provides it. An unticked row is either a ticket or an agreed "dropped, because…".
