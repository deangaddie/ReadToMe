# Read2Me — Domain Context

Domain vocabulary for ReadToMe. Use these terms exactly in code, tests, and discussion. When a new load-bearing concept is named, add it here.

## Book structure

- **Volume / Part / Chapter / Paragraph / ParagraphItem** — the book hierarchy, top to leaf. A Paragraph holds ordered ParagraphItems. An item is one of: **Character** (spoken dialog needing attribution), **Narration**, or a **Pause** kind.
- **Book Hierarchy** — the in-memory `BookHierarchy` that plans structural mutations (split / merge / title / pause insertion) and returns a `HierarchyMutation` (ToAdd / ToDelete / ToUpdate). The deep planning module; `BookCommandHandler` dispatches commands to it.

## Characters

- **Alias** — an alternate name for a Character (e.g. "Mr. Baggins" for "Bilbo Baggins"). Stored in the `CharacterAliases` table. Aliases are injected into the LLM attribution prompt alongside the canonical name and matched case-insensitively by the queue worker, so an alternate name returned by the LLM resolves to the existing canonical Character instead of creating a duplicate.

## Voice rules

- **Voice** — a single synthesizable voice owned by a Character (uploaded reference audio or generated). A Character has many Voices. There is no longer a "default voice" flag on Voice; which voice is the default is expressed by the Character's **default Voice Rule** (see below).
- **Voice Rule** — an ordered, per-Character rule that selects which **Voice** to use for the Character's audio items over a **position range** in the story. A Character owns an ordered list of Voice Rules. Stored in `VoiceRules`. Fields: target `VoiceId`, fractional `Rank` (BINARY-collated, like every other order key), `IsDefault`, and a `From`/`To` bound pair, each a nullable `(VoiceAnchorLevel Level, Guid NodeId)`.
- **Default Voice Rule** — every Character with at least one Voice has exactly one rule with `IsDefault = true`. Its anchors are null (matches the whole story), it is pinned to the top (lowest `Rank`), and it is **not deletable or reorderable**. Created automatically when the Character's first Voice is added (that voice becomes the default's target). "Update the default voice" = repoint the default rule's `VoiceId`. Deleting its target Voice repoints it to the oldest remaining Voice; deleting the last Voice deletes the default rule too.
- **Position** — an audio item's absolute place in the story: the lexicographic tuple `(Volume.Order, Part.Order, Chapter.Order, Paragraph.Order, ParagraphItem.Order)` of sibling-scoped `Order` keys up its ancestry. Compared tuple-wise (Volume first, ties break downward).
- **Anchor** (`VoiceAnchorLevel { Volume, Part, Chapter, Paragraph, ParagraphItem }`) — a Voice Rule bound is `(Level, NodeId)`. The node resolves to a Position **span**: `From` to its subtree minimum, `To` to its subtree maximum. `From = To = chapterNode` ⇒ the whole chapter subtree. `From` set, `To` null ⇒ open-ended forward (e.g. a Character grows up and keeps the new voice from a point on). Both null ⇒ matches everything (the default rule).
- **Voice Rule evaluation** — rules are evaluated **top to bottom by `Rank` ascending; the last passing rule wins**. A rule passes when the item's Position falls inside its resolved `[from, to]` span. The default rule (null anchors) always passes, so there is always a result. The pure `VoiceRuleEvaluator` (no DB — takes the ordered rules plus the item's Position, returns a `VoiceId`) owns the algorithm; the **`VoiceResolver`** (below) owns the data loading that feeds it. The resolved speaker (after `NarratorOnlyMode` / Narration → Narrator substitution) is the Character whose rules are used — the Narrator runs through the same evaluator as any Character.
- **`VoiceResolver`** (`IVoiceResolver`, in `Read2Me.Services.Voice`) — the single seam that answers "which Voice plays each of these items?" Takes a `folder` + a **set** of `ParagraphItem` ids; returns `Dictionary<itemId, Guid?>` (resolved `VoiceId`, null = no voice). Owns the whole computation: reads `NarratorOnlyMode`, applies Narrator substitution to get each item's **effective Character**, then in a **constant** number of queries (~8 regardless of item or character count) batch-loads item positions, each effective character's rules **once**, and every rule's anchor node-orders **once** globally, and runs `VoiceRuleEvaluator` per item. Replaces the former duplicated pair (`GetVoiceRuleInputsAsync` + `GetResolvedVoiceNamesAsync` on `ProjectReader`, which loaded rules + anchors **per item** — an N+1). Two consumers: the `AudioItemResolver` (single-item set → `VoiceId`, then loads the full Voice entity itself) and the Resolved voice preview (batch). A sister `ResolveNamesAsync` adds one batched `Voices` name lookup over the distinct resolved ids for the preview's display shape. Depends on `ProjectDbSession` (same read-side session as `ProjectReader`); the anchor-order batches (`CollectId` + the five node-level order queries) live here, not in `ProjectReader`. The per-rule anchor→span transform is delegated to the pure **`AnchorSpanResolver`** (below).
- **`NodeOrderTables`** — the resolved order data the pure span layer needs: the five per-level lookups (Volume / Part / Chapter / Paragraph order strings, and full `StoryPosition`s for ParagraphItem anchors) batch-loaded by `VoiceResolver`. Owns `TryResolve(level, nodeId, isMin, out StoryPosition)` — the level→`StoryPosition` mapping that pads a node's known orders with `StoryPosition.MinKey` / `MaxKey` to form a subtree-min (`isMin`) or subtree-max bound, and reports a missing node (a **dangling anchor**) by returning false. The single home of the min/max sentinel convention alongside the `StoryPosition` it bounds.
- **`AnchorSpanResolver`** — the pure module that turns one Voice Rule plus a `NodeOrderTables` into a `RuleInput`: resolves the rule's `From`/`To` bounds via `TryResolve`, combines them into the rule's dangling flag and resolved span, and carries through `VoiceId` / `Rank` / `IsDefault`. No DB. The deepened seam extracted from `VoiceResolver`'s former inline span loop, so the subtle span/dangling logic is unit-testable without a database. Feeds `VoiceRuleEvaluator`.
- **Dangling anchor** — a Voice Rule whose anchor `NodeId` no longer exists (any structural change — split / merge / **reread** — regenerates node ids; reread preserves Characters and Voices but clears all Volume…ParagraphItem rows). Such a rule is **skipped** at evaluation (treated as not-passing) and **flagged in the UI** as needing re-anchoring — never silently deleted. (Cascade-delete only applies when the rule's *target Voice* is deleted.)
- **Voice Rule editor** — the per-Character Voice Rules section lives inside `CharacterDetailPanel`, below the voices list. Rules are reordered with up/down arrows (default rule pinned top, not movable/deletable). The per-voice "set as default" star is kept as a one-click shortcut that repoints the default rule's target. New rules are created via a **mode-based editor** — *From here on* (`From = node, To = null`) or *Just this node* (`From = To = node`); a *Range* mode is deferred. The anchor node is chosen with **cascading dropdowns** (Volume → Part → Chapter → Paragraph → ParagraphItem; stop at any level — the deepest chosen is the anchor). Rule creation goes through a UI-agnostic `CreateVoiceRuleCommand` so a future "add rule from book selection" entry point can reuse it. A dangling rule shows a warning + "re-anchor" on its row (the missing node renders as "(missing node)").
- **Resolved voice preview** — `SplitAudio` view shows, per Character item, the Voice that *will* play, computed by the same **`VoiceResolver`** the audio pipeline uses (`ResolveNamesAsync`) — one loader + one evaluator, so preview and playback cannot drift. A dangling rule needs no special preview treatment — it simply doesn't match, and the item shows whichever rule actually wins (often the default).

## Character attribution

- **Character attribution** — deciding which Character speaks a given Character ParagraphItem, via the LLM. A paragraph with unattributed Character items is **unprocessed**; once a Character is assigned it is **processed**.
- **Character Queue** — the background pipeline. The user adds paragraphs to it; `CharacterQueueWorker` drains it and calls `CharacterAttributionService` per paragraph. `CharacterQueueService` holds queue state (queued / processing / outcome) keyed by `(folder, paragraphId)`.

## Book view

- **Book View Mode** (`BookViewMode { Combined, SplitAttribution, SplitAudio }`) — three mutually exclusive display states for the book tab, selected via a single dropdown toggle. `Combined` shows original paragraphs with attribution checkboxes. `SplitAttribution` shows split ParagraphItems with Character-paragraph checkboxes for the attribution queue. `SplitAudio` shows split ParagraphItems with per-item checkboxes for the audio queue plus play buttons. Replaces the old `bool SplitView`.

## Selection

- **Folder Selection** (`FolderSelection`) — the set of Character paragraphs the user has selected (per project folder) for adding to the Character Queue. The single source of truth is the set of selected paragraph ids plus each one's ancestry `(VolumeId, PartId, ChapterId)`.
- **Roll-up** — a node's tri-state (Unchecked / Indeterminate / Checked) is **derived** from how many of its selectable Character paragraphs are selected versus its total count. Node check-state is never stored; it is computed on read. Selecting a node selects all (or, for **unprocessed-only**, the unprocessed subset of) its Character paragraphs; selection is additive and idempotent.
- **Book Node Level** (`BookNodeLevel { Volume, Part, Chapter }`, in Core) — the selectable triad of the hierarchy. The single enum used by both the reader (to scope Character-paragraph queries) and Folder Selection (to derive roll-up). Replaces the old `SelectionNodeKind`.
- **Selectable node** — a Volume / Part / Chapter containing at least one Character paragraph. Only selectable nodes show a checkbox. Node total counts (`NodeCharacterParagraphCounts`) are seeded on load and held by `FolderSelection`. Selection is always cleared on any structural change (split / merge / reread), so derived state never mixes counts from one structure with selections from another.
- **Audio Item Selection** (`AudioItemSelection`) — the set of ParagraphItems (Character or Narration only; Pause excluded) the user has selected for adding to the Audio Queue. Parallel to `FolderSelection` but selects at ParagraphItem granularity, not Paragraph. Rolls up to Chapter/Part/Volume nodes for tri-state checkboxes. Cleared on view mode switch or any structural change (split / merge / reread).
- **Generatable item** — a non-Pause ParagraphItem that can actually have audio generated: it is **missing audio** (no WAV) **and** **attribution-ready** (a Narration item always qualifies; a Character item qualifies only once it has a Character assigned). The audio analog of an **unprocessed** attribution paragraph. The node-level "select needs audio" control (`needsAudioOnly`) selects only Generatable items beneath a node; the per-item checkbox for an unattributed Character item is disabled because it is not yet Generatable. A node's audio roll-up denominator still counts *all* non-Pause items, so a needs-audio select lands on Indeterminate, never Checked — same as "select unprocessed" for attribution.

## Node status

- **Node Status Badge** — a per-node (Volume / Part / Chapter) summary count of remaining work shown in the expansion-panel header. Three **stages**: **attribution remaining** (paragraphs with an unattributed Character item), **audio remaining** (paragraphs with a non-Pause item lacking a WAV — counted regardless of attribution), and **review** (paragraphs with an `AudioReview` row in `NeedsReview` state; `Dismissed` excluded). Counts are **normalised to Paragraph granularity** — a paragraph qualifies for a stage if *any* of its items qualify, contributing 1 regardless of item count. A node with all three stages at zero shows a single "done" indicator instead of empty badges. Shown in every Book View Mode.
- **Node Status roll-up** — each node's badge is the **cumulative** count of qualifying paragraphs beneath it (Volume ≥ Part ≥ Chapter); the same paragraph echoes up every ancestor. Held by the singleton `NodeStatusService`, which stores per-paragraph stage **counters** (`unattributed`, `missingAudio`, `review`) plus `(Chapter, Part, Volume)` ancestry. Seeded on load via `IProjectReader.GetNodeStatusSeedAsync` and updated **live**: the `BookHierarchyPresenter` raises **domain events** on the service — `OnCharacterAttributed` (with the paragraph's *remaining* unattributed count, which the service assigns directly), `OnAudioAssigned` (service decrements `missingAudio`), `OnReviewChanged` (service sets the review flag) — after each attribution / audio-assigned / review change. The service owns the counter transition (assign vs decrement); the caller never picks. **Cleared and reseeded** on any structural change (split / merge / reread), never patched incrementally — same discipline as `FolderSelection`.

## Audio

- **Two-pass normalisation** — loudness normalisation to EBU R128 (`I=-16:TP=-1.5:LRA=11`) done as two ffmpeg `loudnorm` invocations: pass 1 measures (`print_format=json`, parsed from stderr), pass 2 applies with the measured values (`linear=true`). If pass-1 JSON can't be parsed, fall back to **single-pass** `loudnorm`; only a hard ffmpeg/exe failure yields **Skipped**. Applied on both the paragraph path (`NormalizeAsync`, loudness-only, skip→original WAV intact) and the upload/reference path (`NormalizeToWavAsync`).
- **`NormalizeToWavAsync`** — the upload/reference-audio contract on `IAudioNormalizer`: input is *any* ffmpeg-decodable format, output is **always** a **Canonical reference WAV** (or it throws). Distinct from `NormalizeAsync` (which returns the original on skip and never loses audio): there is no "original" fallback here — convert is folded into the two-pass loudnorm (loudnorm output is already WAV PCM); a loudnorm/parse failure degrades to a **bare transcode** (`-i in out.wav`, no filter), and only a decode failure or **absent ffmpeg** throws (surfaced to the user as a snackbar). Shares the two-pass internals with `NormalizeAsync`.
- **Canonical reference WAV** — the fixed output format every uploaded/reference voice audio is standardised to: **24 kHz, mono, 16-bit PCM** (`-ar 24000 -ac 1 -c:a pcm_s16le`), matching chatterbox-native rate. Applied only on the upload path; the paragraph path leaves the TTS service's chosen rate alone. Reference uploads accept **any** ffmpeg-decodable format (no extension allowlist — ffmpeg is the gate) and are always re-encoded to this spec, so the stored file is always `.wav` regardless of source. Normalisation runs on *every* upload, including already-WAV audio (consistent levels across voices).
- **ParagraphItem Audio** — a generated audio file associated with a single ParagraphItem. Visible in `SplitAudio` view only. A ParagraphItem row shows a play button when an audio file exists; tapping it opens an inline player. No audio file → no play button.
- **Audio Queue** — the background pipeline that generates audio for selected ParagraphItems. The user adds items via `AudioItemSelection`; the queue processes them one at a time using the Character's voice (for Character items) or the narrator voice (for Narration items).
- **Audio Gen Stream** — the live per-item progression shown in the expandable `AudioQueueStatusBar`. `AudioQueueProcessor` publishes typed `AudioGenEvent`s to `EventBroadcaster<AudioGenEvent>`; the expandable view accumulates one card per processed item and tail-scrolls to the newest. Mirrors the LLM `EventBroadcaster<LlmStreamEvent>` / `LlmStreamView` pattern. Each card shows the line Character, source text, and four pipeline **phases** — audio generation, normalize, Whisper transcribe, verify — each rendered Pending (spinner) → Done/Fail as its event arrives.
- **Phase fail vs Item failure** — a **phase fail** (normalize ✗ or verify ✗) means the audio was still stored and the item completed; it surfaces as an `AudioReview`. An **Item failure** (`AudioGenEvent` Failed) is a hard stop with no audio (row missing, no character, no voice, no TTS config, or exception). The Audio Gen Stream card renders these distinctly: a phase ✗ on one row vs a terminal red error.
- **Audio Retry** — when an attempt's audio **fails verify** (a transcript exists, `wer > WerThreshold`, and Semantic Rescue did not save it), the `AudioQueueProcessor` regenerates the item up to **`AudioMaxAttempts`** times (app-wide `AppSettings` knob, **total** attempts incl. the first, default **1** = no retry; edited in **Audio Processing** settings). The retry loop lives **inside** one `ProcessItemAsync` call (item dequeued once; all attempts contiguous). Only **verify** failure retries — normalize ✗, transcription-infra failures (no config / Whisper down), and hard **Item failures** never retry. The loop breaks on the first verify pass or when attempts are exhausted; **only the final attempt is persisted** ({id}.wav + audio path + `AudioReview` row), so intermediate attempts generate/normalize/verify in memory and broadcast events but write nothing. An exhausted-and-still-failing item is `MarkComplete` (a verify phase fail surfacing as an `AudioReview`), never `MarkFailed`. Each attempt is a **new card** in the Audio Gen Stream — every `AudioGenEvent` carries a 1-based `Attempt`, the stream model keys cards by `(Id, Attempt)`, and attempts after the first show a **"retry N"** chip (N = Attempt − 1).
- **`IAudioItemPipeline`** — the deep module seam wrapping the four audio production phases for a single ParagraphItem: TTS generate → normalize → transcribe → verify (including Audio Retry and Semantic Rescue). Takes a **`PipelineRequest`** of resolved primitives (source text, voice, TTS config, ref audio path, thresholds); returns a **`PipelineResult`**. Broadcasts per-attempt `AudioGenEvent`s directly to `AudioGenBroadcaster`. Throws on hard unrecoverable failure (TTS exception, filesystem exception); the caller (`AudioQueueProcessor`) catches and publishes `Failed`. Phase fails (normalize ✗, verify ✗) are not exceptions — they surface in `PipelineResult` as `NormalizeOutcome.Ok = false` / `VerifyOutcome.Ok = false`. Lives in `Read2Me.Services.Audio`.
- **`PipelineRequest`** — the resolved inputs to `IAudioItemPipeline`: `ParagraphItemId`, `SourceText` (original, for WER verify; trailing-comma substitution applied internally by pipeline), `Speaker`, `VoiceInstructions`, `RefAudioPath`, `ParagraphTtsServiceConfig`, `TtsSettingsOverrideJson`, `MaxAttempts`, `WerThreshold`, `FfmpegPath`. Produced by `IAudioItemResolver` — the pipeline never loads DB rows itself.
- **`IAudioItemResolver`** — the seam that owns the Audio Queue setup phase for a single ParagraphItem: DB queries (item row, NarratorOnlyMode, voice), Voice Rule evaluation, TTS config loading, and ref-audio path construction. Takes a `QueuedAudioItem`; returns a **`ResolutionResult`**. Lives in `Read2Me.Services.Audio`. Has no dependency on `EventBroadcaster<AudioGenEvent>` or `AudioQueueService` — those stay in `AudioQueueProcessor`.
- **`ResolutionResult`** — what `IAudioItemResolver` returns: `Speaker` (string?), `SourceText` (string?), `Request` (`PipelineRequest?` — null on failure), `FailureReason` (string? — null on success). `Succeeded = Request is not null`. The processor publishes `ItemStarted(Speaker, SourceText)` unconditionally before branching on `Succeeded` — handles both the "row not found" null case and the success case with one code path.
- **`PipelineResult`** — what `IAudioItemPipeline` returns on success: `AudioBytes` (final attempt WAV, in-memory), `NormalizeOutcome`, `VerifyOutcome`. Callers persist `AudioBytes` to disk and write commands from the outcome fields.
- **`IAudioResultRecorder`** — the seam that durably records a `PipelineResult` for one ParagraphItem: writes `{id}.wav` under `audio/`, issues `SetParagraphItemAudioCommand` + `SetAudioReviewCommand`, and applies the `AudioReviewService` cache transition (both phases ok → `Clear`; any phase fail → `Set(NeedsReview)`). Returns the audio **relative path** (`audio/{id}.wav`) so the `AudioQueueProcessor` can `MarkComplete` without re-deriving the filename convention. Owns the filename convention as single source of truth. Lives in `Read2Me.Services.Audio`. Completes the resolve → pipeline → **record** seam trio; the processor keeps only queue-mark transitions, `ItemStarted`/`Failed` publishing, and the try/catch envelope.
- **`NormalizeOutcome`** — phase result nested in `PipelineResult`: `Ok` (bool), `Reason` (string?). Matches the normalize phase of Phase fail vs Item failure.
- **`VerifyOutcome`** — phase result nested in `PipelineResult`: `Ok` (bool), `Wer` (double?), `Reason` (string?), `Transcript` (string?), `Rescued` (bool). Matches the verify phase of Phase fail vs Item failure, including Semantic Rescue flag.

## Semantic verification

- **Semantic Similarity Check** — an embedding-based comparison of two strings (original source text vs Whisper transcript) that returns a cosine **similarity score** in `[0,1]` (higher = closer in meaning). Served by local sentence-transformer containers — `read2me-minilm-l6` (8200) and `read2me-mpnet-base-v2` (8201) — each exposing `POST /similarity` with `{text1, text2}` → `{similarity}`. Configured exactly like Transcription: many named **Semantic Similarity configs** (`Name` / `Type` ∈ `{MiniLmL6, MpnetBaseV2}` / `SettingsJson`), one **active**, managed by a `ServiceConfigStore`. The per-config `SettingsJson` carries `BaseUrl` **and** a `PassThreshold` (default **0.85**) — the threshold lives with the provider because the two models have different score scales. A **pass** is `score >= PassThreshold`. Inputs are sent **raw** (no WER-style normalisation — embeddings handle paraphrase, number-words, punctuation natively).
- **Semantic Rescue** — the WER-fallback in the verify stage. When a clip **fails WER** (`wer > WerThreshold`, a transcript exists) **and** a Semantic Similarity config is active, the original source text and the transcript are sent to the active config's `/similarity`. If `score >= PassThreshold` the item is **rescued**: its verify outcome flips to **pass** (`verifyOk = true`, no review row), while the over-threshold `wer` is **retained** and the reason records the rescue (e.g. `"WER 0.22 > 0.15; rescued by semantic 0.91 ≥ 0.85"`). If the semantic score also falls short, the original WER fail stands. Rescue is **best-effort and never worsens an outcome**: no active semantic config, or any `/similarity` HTTP/exception, is swallowed (logged warning) and leaves the WER fail intact — the semantic container being down can never crash or block the Audio Queue. Owned by a thin **`ISemanticVerifier`** seam (`PassesAsync(source, transcript, ct)`), keeping `AudioQueueProcessor` and the WER path otherwise unchanged. A rescued item broadcasts `Verified(Ok: true, Wer, reason, Rescued: true)`; the Audio Gen Stream's verify row shows a green check plus a **"rescued"** chip.

## Sentence chunking

- **Sentence Chunking** — splitting a ParagraphItem's text into individual sentences, synthesising each separately, then stitching the per-sentence audio back into one item-level WAV. Long text sent to a TTS service in one call can peak / produce artifacts; per-sentence calls avoid it. Applied transparently inside the TTS layer — the rest of the audio pipeline (normalize, store one `{id}.wav`, Whisper verify against the full source text) is unchanged. Verify still scores the whole stitched item, not per sentence.
- **`SentenceChunkedTtsClient`** — the decorator over `IParagraphTtsClient` that owns chunking. It **self-gates**: when `SentenceSplitEnabled` is off it passes the text straight to the inner client. Wired in by `ParagraphTtsClientResolver`, so every TTS service type is wrapped and `AudioQueueProcessor` stays unaware of chunking. One chunk (or a short item) stitches to a byte-identical passthrough.
- **Sentence Pause** (`SentencePauseMs`) — silence inserted **between** adjacent sentences when stitching (N chunks → N−1 gaps; no leading/trailing silence, so inter-item spacing is unchanged). Zero-PCM samples spliced into the WAV `data`.
- **Min chunk** (`SentenceMinChunkChars`) — a sentence fragment shorter than this is merged into its neighbour, so titles / short exclamations ("Mr.", "Yes.") don't become their own micro-chunk. Internal tuning knob — stored but not surfaced in the UI.
- **Chunk failure** — if any one sentence's TTS call throws, the whole item fails (the decorator throws; the processor's existing catch marks it an Item failure). No partial / gappy audio is ever stored.

## Audiobook assembly

- **Audiobook Assembly** — combining every ParagraphItem's WAV, plus silence for Pause items, into one **m4b** (AAC) per project with embedded **chapter markers**, **cover**, and metadata. Triggered by a single **Assemble** toolbar button (always visible, all view modes). One project = one assembly. Output: `{projectFolder}/output/{sanitized BookTitle}.m4b`, overwritten each run. Distinct from the per-item Audio Queue — this is a **single long job**, not a queue of items.
- **Assembly Service** (dedicated job runner, not `QueueWorker<T>`) — a **single-flight** background task started by the Assemble button. **Gated**: disabled while an assembly runs *and* while the Audio Queue has in-flight items for that project (output would be stale). **Cancellable** via the status bar (mirrors `AudioQueueStatusBar`). Reads a **DB snapshot at start** (`GetAssemblyManifestAsync`), so book edits mid-run don't corrupt the output — it reflects the start state.
- **Assembly precondition** — assembly is **blocked** unless every non-Pause item across the book has a WAV. Reuses the node-status **audio-remaining** count (paragraphs with a non-Pause item lacking a WAV). Pauses need no audio (they are silence). No gappy / placeholder output is ever produced; the button is disabled with "N items still need audio".
- **Assembly Manifest** (`IProjectReader.GetAssemblyManifestAsync(folder)`) — the ordered item stream the assembler walks, in **Position** order (Volume→Part→Chapter→Paragraph→ParagraphItem, same tuple as voice rules). Each entry carries item id, `ItemType`, audio relative path (or null for pauses), and section ancestry (Volume/Part/Chapter ids + titles) for chapter markers.
- **Pause durations** (`AppSettings`, per-kind ms) — Pause items store only a *kind*, no duration; the assembler maps kind→ms from app-wide settings: `VolumePauseMs` (4000), `PartPauseMs` (3000), `ChapterPauseMs` (2500), `ParagraphPauseMs` (800), `PauseMs` (500). Editable in **Audio Processing** settings. The longer Volume/Part/Chapter pauses are what separate sections inline.
- **Silence segments** — concat needs silence as real files in the **Canonical reference WAV** format (24 kHz mono 16-bit PCM). Generated via ffmpeg `anullsrc` (`-f lavfi -i anullsrc=r=24000:cl=mono -t {sec} -c:a pcm_s16le`), **cached per distinct ms** for the run (~5 files max).
- **Concat assembly** — one ffmpeg pass over the **concat demuxer**: a concat list interleaving item WAVs and silence segments, decoded and encoded to **AAC** once (`-c:a aac -b:a 64k -ac 1 -ar 24000`), muxed to m4b. Chapter timestamps computed from per-input durations (item WAVs probed via ffprobe; silence durations known exactly). Single encode = best quality + correct timestamps.
- **Chapter markers** — each **section** (Volume / Part / Chapter) becomes its **own** m4b chapter; the marker lands at the start of that section's first audio item (its **title narration** — titles are ordinary Narration items, see `TitleInserter`, not a special type). m4b chapters are **flat**; nested levels each emit a marker labelled by node title (fallback "Chapter N"). Written via an **ffmetadata** file (`-f ffmetadata` `[CHAPTER]` blocks + `-map_metadata`).
- **m4b metadata + cover** — standard audiobook tags: `title`=BookTitle, `artist`+`album_artist`=Author, `album`=BookTitle, `genre`=Audiobook. Cover (`Project.CoverImage`, relative jpg path, nullable) embedded as `-c:v mjpeg -disposition:v attached_pic`; **null cover → no cover stream** (not an error).
- **Assembly progress** — coarse **phases** broadcast to a status bar (gather manifest → generate silence → probe durations / build concat → **encode m4b** → finalize). The encode phase shows a **live %** parsed from ffmpeg stderr `time=` against total known duration. Mirrors the `EventBroadcaster<AudioGenEvent>` / status-bar pattern; no per-item cards.
- **Assembly failure** — encode writes to `{title}.m4b.tmp`, **atomic rename** on success, temp deleted on failure (never leaves a truncated m4b). A hard ffmpeg/disk failure broadcasts a **terminal Failed** event with the ffmpeg stderr tail (red status bar); **ffmpeg-absent** reuses the normalizer's "set the path in Audio Processing settings" message.
- **`EventBroadcaster<T>`** — the generic singleton bridge for live streaming events: a scoped producer calls `Publish`; a singleton-subscribed Blazor view receives via `Event` (marshalled with `InvokeAsync(StateHasChanged)`). One transport carries every event family (`LlmStreamEvent`, `AudioGenEvent`, `AssemblyEvent`, `VoiceBatchEvent`); each is a distinct closed-generic singleton. Replaces the former per-feature broadcaster shells.
- **`VoiceBatchRunner`** — the singleton that runs one Voice Batch sweep (characters-tab "generate prompts / audio for all") over a Sweep Phase, owning the invariant envelope: the async scope, the foreach, cancellation, the live counters (`Total`/`Processed`/`Failed`/`CurrentVoiceName`/`CurrentOperation`) and their locking, and the `BatchStarted → BatchProgress → VoiceUpdated → BatchCompleted/BatchCancelled` sequence published to `EventBroadcaster<VoiceBatchEvent>`. The UI binds its polled state and calls `Cancel()`. Its pure inner method `RunPhaseAsync<TWork>` takes an already-built `PhaseDeps` (no scope creation) and is the unit under test.
- **Sweep Phase** (`ISweepPhase<TWork>`) — one voice-batch phase = a filter (`PlanAsync` → the work list, free to issue the pre-step DB writes that decide what to process) + a per-item step (`RunStepAsync` → a `PhaseStepOutcome` of ok/soft-fail plus the `VoiceUpdated` payload) + a `DisplayName`. The phase owns only what-to-process and what-to-do; the `VoiceBatchRunner` owns the envelope. Two phases today: `GeneratePromptsPhase`, `GenerateAudioPhase`.
